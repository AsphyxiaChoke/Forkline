# Forkline

Forkline 是一个中文 Git 可视化管理工具，界面和操作方式参考 GitKraken。

它在本机启动一个 Web 页面，直接管理电脑上的 Git 仓库。日常提交、分支切换、同步、冲突处理和历史查看都可以在界面中完成。

## 快速开始

### 运行要求

- Windows 电脑。
- 已安装 Git，并可在命令行执行 `git`。
- 使用 Release 中的 Electron 安装版或 Web 便携包时不需要安装 Node.js；使用 Git 源码仓库时需安装 Node.js，并可在命令行执行 `node`。

运行所需文件已经放在仓库中，不需要执行 `npm install`。

### 启动 Forkline

1. Electron 安装版从桌面或开始菜单打开 `Forkline`；Web 便携包双击 `Forkline.cmd`；Git 源码仓库双击 `start.cmd`。
2. Electron 安装版会直接打开独立窗口；Web 版会自动打开浏览器。
3. 第一次使用时，在顶部输入或选择本机 Git 仓库路径。
4. 点击“打开”；以后再次启动会自动恢复上次成功打开的仓库。

如果浏览器没有自动打开，请手动访问：

```text
http://127.0.0.1:5177
```

关闭 `start.cmd` 的命令窗口后，本地服务也会停止。

如果上次仓库已移动、删除或不再是 Git 仓库，Forkline 会回到示例页面，可重新选择仓库。

### Electron 桌面版

Electron 版直接复用当前 Web 界面和全部 Git 功能，不需要手动启动服务或打开浏览器。Release 中的 `Forkline-Setup-*-windows-x64.exe` 按当前用户安装，允许选择目录，并默认创建桌面和开始菜单快捷方式。源码试用可先执行 `npm.cmd install`，之后双击 `start-electron.cmd`；也可以把仓库路径作为参数传入，例如 `start-electron.cmd "D:\桌面\GitTest"`。桌面版默认使用 `90%` 界面缩放，可在“设置 -> 界面缩放”中切换，也支持 `Ctrl+-`、`Ctrl++` 和 `Ctrl+0`；关闭后会记住上次所在屏幕、普通窗口尺寸和最大化状态。详细说明见 [Electron 桌面版说明](docs/ELECTRON_DESKTOP.md)。

切换六套界面皮肤时，Electron 最上方标题栏以及右上角最小化、最大化、关闭按钮会同步使用当前皮肤的背景色和图标色。`v0.4.1` 起 Release 同时自动提供 Electron 安装器和 Web 便携 ZIP。当前安装器没有代码签名，Windows 可能显示“未知发布者”或 SmartScreen 提示；请只从官方 Release 下载并按同页 SHA-256 文件核验。

Electron 的主题、语言、布局和界面诊断等偏好保存在 Forkline 本机用户数据中，普通重启、覆盖安装和应用内更新后都会保留。`v0.4.6` 起，本机保存失败时会恢复最后一次已经确认落盘的值并在界面提示，写入中断也会保留上一份完整偏好文件；普通 Web 浏览器和 Web 便携版仍使用当前浏览器来源的存储。

`v0.4.8` 将 Electron 从 `43.4.0` 更新到 `43.4.1`，纳入 Windows 在系统“打开方式”对话框等待期间无法退出、主进程退出崩溃、BrowserWindow 内存泄漏以及受系统策略阻止原生解压时安装失败的修复；提交详情正文在支持 `field-sizing` 的浏览器中按完整内容展开，旧浏览器保留可滚动回退；Web、Web 便携版、Git 语义和安装版更新分流均不改变。

`v0.4.21` 恢复 Electron 独立历史和普通冲突窗口的完整 MergeView，重新提供差异连线、行对齐和语法高亮；复杂文件仍使用轻量 CodeMirror。快速滚轮由 Forkline 在捕获阶段先于 CodeMirror 接管，只移动用户正在操作的栏，停止 `200 ms` 后再同步其他栏一次；快速拖动滚动条也不会逐帧反复回写目标栏。独立编辑器现在是任务栏可见的顶层窗口，最大化时内容会随窗口完整铺满。Web 页面、工作区编辑和 Git 操作语义保持不变。

如果页面暂时无响应，桌面版会先给大文件和差异计算留出恢复时间，再提示“继续等待”或明确放弃未保存内容后重新加载；页面进程崩溃时会显示原因并让用户选择重载或退出。普通重载会尝试恢复提交摘要、正文、追加状态和未保存的文件编辑内容；如果文件已被其他程序改动，会改为“磁盘当前版本 / 恢复草稿”只读对照，避免旧草稿直接覆盖新内容。草稿只保存在当前 Electron 主进程内存，退出 Forkline 后不会继续保留。

Forkline 已经运行时，再通过 `start-electron.cmd "仓库路径"` 启动不会创建第二套窗口和后台服务，而是把现有窗口拉到前台并打开指定仓库。页面还在启动时连续传入多个路径会保留最新一个；切换仓库、克隆后打开或初始化后打开之前，如果文件编辑器或提交信息框有未保存内容，会先列出风险并要求确认。

退出桌面版时，Forkline 会先停止接收新请求，再结束自己启动的 Git/SSH 子进程和后台服务。优雅退出超时后只会针对当前桌面实例持有的后台进程树兜底，不按进程名扫描，也不会结束其他终端或 Git 工具中的进程。

## 界面说明

- 左侧：本地分支、远端分支、Tag 和仓库入口。
- 中间：提交图谱、提交列表，以及工作区、暂存区和提交编辑。
- 右侧：当前提交详情、变更文件、同步、储藏、分支整理、恢复点等工具。
- 分隔线：可以拖动左侧栏、右侧栏、图谱列和底部工作台，调整显示空间。

图谱列较窄时，长分支名会省略；拉宽图谱列后会自动显示更多内容，鼠标悬停也能查看完整名称。
提交历史默认载入最近 120 条，滚动到底部后可以继续加载更早提交。
已载入的提交超过 240 条时，提交列表和图谱只渲染当前可视区域附近的内容；搜索、深度滚动和跳转旧提交仍使用完整历史数据，不会因为加载到几千条提交而一次生成全部页面节点。
打开或切换仓库时，会先显示仓库、分支、同步摘要和当前分支历史，再通过专用补充接口读取工作区快照、Tag 和完整分支元数据，不会重复读取首屏已有的远端、同步与历史。当前分支优先直接读取 worktree 的 `.git/HEAD`，异常结构才回退 Git 命令；本地/远端分支、tracking、提交元数据和 Tag 会从合并后的引用快照中拆分，避免为同一批引用重复启动 Git。分支 tracking 已提供的领先/落后、上游丢失状态和远端 SHA 会直接复用。最近两个仓库各自保留有界的工作区监视与快照，切回来且文件没有变化时直接复用；文件事件、Git 索引变化、超过安全复查时间或进入第三个仓库都会使对应缓存重新校验。分支整理、工作树、子模块、储藏和恢复点改为打开对应右侧页签时读取。核心状态载入期间工作区会明确显示进度，不会误显示为“没有修改”，写操作会等核心快照就绪后再执行；页签详情失败时会显示错误与重试入口。真实 Chromium 回归中，12 次大/小仓库切换约 `2.60 s`，`/api/open` 中位约 `99 ms`、补充接口约 `80 ms`，4000 文件仓库的渐进首屏约 `115 ms`、完整补齐约 `247 ms`。
打开仓库不会自动执行 `git fetch`。即使仓库配置的远端暂时不可用，Forkline 仍使用本地分支、remote-tracking 引用和提交打开；浏览器对 `/api/open` 的一次瞬时网络失败会自动重试，补充详情请求失败时会回退到本地核心状态并显示中文提示。只有本地服务也无法读取工作区时才继续保护写操作，已经载入的提交历史仍可查看，不会把仓库永久卡在加载状态。
提交、签出、合并、变基、同步、远端管理和冲突继续/中止完成后，只等待核心仓库状态回填，不再同步读取分支整理、工作树、子模块、储藏和恢复点；这些页签会在需要时重新载入。真实 Chromium 中该状态回填约 `59 ms`，操作完成后的图谱和工作区会更早恢复可用。
从示例页首次打开真实仓库时，即使文件编辑器尚未载入，页面也会完整切换到新仓库并与后台状态保持一致。
页面可见且有焦点时，工作区会从 5 秒开始静默检查；工作区达到 800 个文件且连续没有变化时，间隔会逐步放宽到 10、20、30 秒，重新聚焦或发现变化后立即恢复为 5 秒。后台始终先核对轻量 Git 状态；状态相同且没有文件事件时复用最近快照，具体文件变化只重新计算对应文件，目录事件只重算该目录内的状态项。Git 索引变化、路径不明确、监听不可用或超过 60 秒都会完整扫描。没有变化时只返回快照和未完成操作状态，不会重新传输或重建整棵文件列表；小工作区、手动刷新和储藏操作保持原有响应速度与完整数据。
首次完整扫描仍会计算文件内容 SHA-256，保证后续 Git 写操作不会误用过期工作区；读取时复用同一个文件句柄，4000 文件真实 Chromium 回归中的冷 API 已从约 460 ms 降到 306-307 ms。
工作区文件很多时会先显示 800 个，滚动到底部后每次继续显示 100 个；屏幕外目录会连同内部文件一起暂停布局和绘制，并按完整文件数量预留滚动高度，目录层级、折叠、选择、双击和全部文件访问保持不变。滚动追加采用有界的小批次，不强制改写原生 `scrollTop`，高速连续向下滚轮可以继续触发后续批次，避免大量分散目录在滚动时长时间阻塞界面。
提交详情中的“历史编辑”和“历史编辑队列”默认折叠；已有预检计划或队列内容时会自动展开。

## 常用操作

### 提交修改

1. 在“工作区”选择文件并查看改动。
2. 暂存整个文件，或在 Diff / 文件编辑器中暂存指定块、指定行。
3. 在“提交编辑”填写摘要和正文。
4. 点击“提交”。

勾选“追加”后，会载入最近一次提交的信息，并把本次暂存内容补进最近一次提交。这个操作会改变最近一次提交的 SHA。

### 查看和编辑文件

- 双击工作区文件：打开可编辑的新旧文件对照。
- 文件编辑器专用样式、CodeMirror 和编辑器实现会在第一次打开文件时载入；互不依赖的 CodeMirror 插件和语言模式会并行读取，存在依赖的模式与 Forkline 编辑器模块仍按顺序执行。后续打开直接复用，只浏览提交图和工作区列表时不会预先解析这些资源。
- 默认中文界面不会预先载入完整英文词典；第一次切换到英语时才加载，之后在本次页面中直接复用。
- “设置”“储藏”“标签列表”“恢复点”“分支整理”“工作树”“子模块”“分支比较”“操作日志”以及“文件历史 / 逐行追踪”在第一次打开时才载入，后续直接复用；设置页、分支整理/工作树/子模块、操作日志以及文件历史/逐行追踪的专用样式也会和对应脚本一起按需载入，并在两者都完成后显示。储藏、标签、恢复点、同步和分支比较共用一份仓库工具面板样式，快速切换这些页面也不会重复加载；分支相关的三个页签以及文件历史/逐行追踪仍分别共用自己的脚本和样式。从分支右键发起比较时会直接进入载入中的比较页，结果返回后显示完整提交和文件差异。资源加载失败时会显示错误和重试入口。恢复点保留策略和危险操作后的整理保护仍在启动时可用；长时间 Git 操作的轮询和取消能力也保持立即可用，只有日志列表和界面诊断页面延后载入。
- 分支比较会并行读取彼此独立的仓库信息，并在一次快照展开中取得两侧提交和共同祖先；计数、两侧提交清单和 Diff 随后同轮读取。所有结果继续使用固定提交 SHA，不会因为比较期间分支引用移动而混用两次状态；快照展开失败时会回退逐项校验并保留原中文错误提示。`D:/桌面/GitTest` 的同一比较接口经过两轮优化从约 `249.1 ms` 降到 `125.9-135.2 ms`。
- 逐行追踪会复用文件路径解析时已经完成的引用存在性检查，正常文件不再重复启动一次相同的 Git 命令；`D:/桌面/GitTest` 的同一文件追踪接口实测从约 `113.2-116.8 ms` 降到 `79.1-82.7 ms`，重命名路径、父提交回溯和无提交分支提示保持原行为。
- “同步情况”的页面布局、待拉取/待推送提交预览、远端管理和认证工具会在第一次打开同步页时一起载入；首屏只保留顶栏和 Git 操作立即需要的同步状态合并、轻量刷新与推送保护。
- 提交、分支、文件、Tag、远端和引用日志的完整右键菜单实现与专用样式会在第一次右键时并行载入，后续直接复用；普通提交点选、菜单定位和关闭仍可立即使用，文件编辑器首次打开时会复用同一份菜单样式。
- 本机目录选择器和命令面板的完整实现与专用样式会在第一次打开任一入口时并行载入，等待两者完成后再显示，后续直接复用；任一资源失败只重试失败项。右侧页签切换与上下文判断仍保留在首屏，不需要先打开命令面板。
- 提交、签出、合并、变基、储藏、远端、单文件和批量文件等完整 Git 操作实现会在第一次实际执行相关命令时载入，后续直接复用；启动时仍立即提供当前分支、工作区和远端快照校验、追加状态，以及“储藏并签出”返回原分支后的自动恢复。
- 挑选、还原、重置、历史编辑、提交补丁、创建 Tag、Pull Request 和分支比较等提交操作会在第一次使用时载入；历史编辑预检、影响提交列表和队列编辑的专用样式会与完整实现并行载入，两者完成后才显示。提交详情所需的历史编辑说明、空队列、远端链接、复制和弹窗关闭仍立即可用。
- 单击工作区或暂存区文件只更新选择和右侧文件上下文，不会在隐藏区域读取或渲染 Diff；右键“查看对照”时才并行载入 Diff 工作台专用样式与实现、读取差异并打开最大化对照，脚本或样式失败时只重试失败项，后续操作直接复用。
- 双击冲突文件：打开“当前版本 / 合并结果 / 对方版本”三栏编辑器；左右版本只读，中间结果可编辑并保存。普通文件在 Web 和 Electron 独立窗口中都使用完整 MergeView，左右差异块按钮可把对应内容应用到中间；复杂文件自动使用轻量 CodeMirror 三栏。
- 双击历史提交中的变更文件：普通文件在 Web 和 Electron 独立窗口中都提供完整 MergeView、差异连线、行对齐和语法高亮；行数、体积或差异复杂度超过保护门限时自动使用轻量 CodeMirror 双栏。
- 右侧“文件”页读取提交详情时，会在同一轮并行读取提交元数据、完整文件清单和按需 Diff，并同时记住第一父提交；合并提交仍按第一父提交展示，随后双击变更文件会复用这个结果，不再重复解析提交关系。12 次切仓回归中的提交详情中位约 `64 ms`；真实 Chromium 通过文件列表双击打开 60000 行历史文件约 `187 ms`，其中提交文件接口约 `49 ms`，主线程最长延迟约 `43 ms`。
- 历史文件行数很多或改动过于分散时，会自动改用轻量双栏并在底部说明原因；普通历史文件仍可切换两种对照方式。
- MergeView 和轻量 CodeMirror 共用受控滚动同步。快速滚轮在捕获阶段阻止 CodeMirror 自己的滚轮预处理，只推动鼠标所在栏的可见滚动条；滚轮、滚动条拖动或键盘滚动停止 `200 ms` 后，目标栏只同步一次最终位置，程序滚动不会反向驱动原栏。MergeView 的同步开关保持原行为。
- 普通文件对照如果实际创建超过约 250ms，会立即改用轻量模式；本次浏览器会话再次打开同一版本时会直接使用轻量模式。
- 历史提交右侧“文件”页只保留可滚动文件清单，避免大提交自动生成整份 Diff；双击文件时才读取完整对照。
- 工作区、历史和冲突代码对照均支持行号、代码高亮、查找替换、GBK / GB18030 和常见 UTF-8 文件；普通 Electron 历史窗口继续保留完整差异视图。
- 不超过 1 MiB 的工作区文本可直接编辑；1 MiB 到 16 MiB 自动使用轻量只读双栏，避免计算大型差异导致卡顿。
- 超过 16 MiB 或识别为二进制的文件会给出明确提示，不会强行载入编辑器。
- 保存、暂存改动块或暂存所选行后，窗口会保留原来的查看位置并显示操作结果；刷新后仍存在的目标改动块会短暂高亮。
- 工作区文件右键“查看对照”支持按块和按行操作；未跟踪文件会说明部分暂存后其余内容仍在工作区，长 Diff 操作后仍停留在原位置。
- 顶栏“撤销 / 恢复”和页面级 `Ctrl+Z` / `Ctrl+Y` 可撤销或恢复最近一次安全的暂存、取消暂存和提交操作；文本框、可编辑区域和 CodeMirror 编辑器仍使用浏览器原生撤销。暂存撤销只恢复 Git 暂存区，不修改工作区文件；仓库状态变化后会自动禁用过期的暂存历史。
- 大型 Diff 只在可见窗口生成一份内容，并按最多 1000 行一批显示；已移除的隐藏对照区域不会再重复渲染。

### 切换分支

- 工作区干净时，可以直接签出目标分支。
- 有未提交修改时，可以先提交、储藏，或者确认后丢弃修改。
- “储藏并签出”创建的临时储藏，在安全条件满足时，切回原分支会自动恢复。
- 手动创建的普通储藏不会自动恢复，需要在“储藏”页应用或弹出。

### 使用储藏

储藏就是把未提交修改临时收起来，让工作区恢复干净。修改没有丢失，会出现在右侧“储藏”页。

- 应用：恢复修改，但保留这条储藏。
- 弹出：恢复修改，成功后删除这条储藏。
- 删除：直接删除储藏，修改不会恢复。
- 从储藏创建分支：新建分支并把储藏内容恢复到该分支。

### 处理冲突

发生合并、变基、挑选或还原冲突时：

1. 打开冲突文件，对照“当前版本 / 合并结果 / 对方版本”。
2. 点击左右差异块的“应用”，或直接编辑中间的合并结果。
3. 保存合并结果，再暂存已经解决的文件；保存本身不会自动暂存。
4. 点击“继续操作”。

不想保留本次操作时，点击对应的“中止”按钮。仓库存在未完成操作时，应先继续或中止，再切换分支。

### 与远端同步

- 抓取：更新远端分支信息，不修改当前工作区。
- 拉取：只接受可以快进的更新，不会自动产生合并提交。
- 变基拉取：把本地未推送提交移动到远端最新提交之后，相关 SHA 可能改变。
- 推送：把当前分支提交发送到远端。
- 安全强推：用于变基、压缩或追加提交之后更新远端，带保护检查，不使用裸 `--force`。
- 打开“同步”页或设置、取消 upstream 时，只刷新当前分支的同步信息和远端分支，不重新读取提交图、工作区或已加载的提交详情。
- 同步页“认证助手”会显示 SSH key、ssh-agent、Git Credential Manager、远端协议和托管平台；每个远端都能直接检查连接，GitHub、GitLab、Bitbucket 还提供平台状态页入口。
- Windows 下可从认证助手打开系统凭据管理器，查看或更新 HTTPS 登录信息。Forkline 不会自动读取、修改或删除其中保存的账号和 Token。
- 克隆、抓取、拉取、推送和子模块更新执行较久时，可在“操作日志”查看当前命令、耗时和最近输出，并点击“取消操作”。
- “操作日志”同时保留最近 40 条界面诊断，包括超过 200ms 的主线程阻塞和未处理前端错误；刷新页面后仍可查看并复制诊断信息。

取消会停止当前 Git 进程，但已经完成的远端传输不会自动回退。取消克隆后，请检查目标目录；Git 可能已经留下未完成的文件，需要确认无用后再手动删除。Windows 拒绝执行 `taskkill` 时，Forkline 会回退为停止自己启动并持有的当前 Git 子进程，同时解除该请求占用的输入输出管道；不会按进程名扫描或终止其他 Git、SSH 进程。

## 历史操作是什么意思

| 操作 | 作用 | 需要注意 |
| --- | --- | --- |
| 挑选 | 把某一个提交的改动复制到当前分支 | 可能产生冲突 |
| 还原 | 新建一个反向提交，撤销目标提交的改动 | 适合已经共享的历史 |
| 软重置 | 移动当前分支位置，改动仍留在暂存区 | 会改变本地历史 |
| 混合重置 | 移动当前分支位置，改动留在工作区但取消暂存 | 会改变本地历史 |
| 硬重置 | 移动当前分支位置，并丢弃工作区和暂存区改动 | 未提交修改可能永久丢失 |
| 压缩进父提交 | 把当前提交与父提交合成一个提交 | 后续提交 SHA 会改变 |
| 修补进父提交 | 合并改动，但丢弃当前提交信息 | 后续提交 SHA 会改变 |
| 丢弃此提交 | 从当前分支历史中移除该提交 | 后续提交 SHA 会改变 |

## 安全说明

- “丢弃全部”和“硬重置”会删除未提交修改，执行前请确认文件不再需要。
- 追加、变基、压缩、修补、丢弃历史提交和修改旧提交信息都会重写 SHA。
- 已经推送并与别人共享的提交，不要随意重写历史。
- Forkline 会在部分危险历史操作前创建恢复点，但恢复点只保存提交位置，不保存未提交文件。
- 创建了自动恢复点的操作完成后，顶栏会临时显示“撤销”；只有仓库、当前分支和 HEAD 都没有变化时可用，工作区有未提交改动时会先禁用。
- 暂存和取消暂存成功后也会生成一次页面级可撤销记录；它只保存 index tree 前后状态，工作区文件内容不随暂存撤销改变。`Ctrl+Y` 或“恢复”会恢复刚才被撤销的暂存/提交操作。
- 恢复点保留策略按仓库分别保存；可勾选“操作后提醒整理”，但 Forkline 只会列出候选并再次确认，不会静默删除恢复点。
- 系统凭据入口只负责打开操作系统界面；删除或修改凭据仍由用户在系统界面中明确完成。
- 页面状态过期、分支或文件被外部程序修改时，Forkline 会拒绝旧操作并要求刷新。
- 建议先在测试仓库熟悉危险操作，再用于重要项目。

## 更新 Forkline

左上角只在发现新版本时显示更新图标；设置页“关于 Forkline”会显示当前版本和检查结果。

- 使用 Git 克隆的官方仓库：位于 `main` 分支且工作区干净时，可在设置页执行“立即更新并重启”。
- 使用 Windows 便携包：包内保留浅层 Git 仓库和官方 `origin`，同样支持“立即更新并重启”，并使用内置 Node.js 启动。
- 使用 Electron 源码桌面版：从官方 Git 克隆运行 `start-electron.cmd` 时，同一按钮会退出整个旧桌面实例，更新后重新打开 Electron；新窗口未能正常显示时会自动回退并重开旧版本。
- 使用 Electron NSIS 安装版：同一按钮通过 `electron-updater` 检查官方 GitHub Release。`v0.4.2` 起，版本和 SHA-512 仍以 GitHub 官方 `latest.yml` 为准，安装器 EXE 与 blockmap 优先通过国内加速节点下载；节点不可用或文件校验失败时会清理失败下载，并自动回退 GitHub 官方完整安装包。下载完成后先确认没有 Git 操作仍在执行，再优雅停止 Forkline 后台服务及其持有的 Git/SSH 子进程；操作未结束或停机失败都会取消安装，不会中断正在写入仓库的命令或在后台服务仍运行时强行覆盖。随后启动安装器并重新打开 Forkline。
- 已安装的 `v0.4.1` 本身不包含加速代码，因此首次升级到 `v0.4.2` 仍使用 GitHub 官方下载；安装或升级到 `v0.4.2` 后，后续安装版应用内更新才会优先使用国内加速。源码克隆、Electron 源码版和 Web 便携版继续使用原有 Git 快进更新，不经过安装包加速节点。
- 更新页会显示准备、停止旧服务、重新校验、写入版本、重启和健康检查 6 个阶段；浏览器和便携 Web 版会在服务重启期间自动重新连接，Electron 源码版则会关闭旧窗口并打开新窗口。
- 准备阶段会显示 GitHub Release 的对象百分比和已接收 KiB/MiB；连接重置、超时、DNS/TLS 或 early EOF 等瞬时下载错误会有限重试，仍失败时不会写入新版本。
- 更新失败时会分别说明文件是否已回退、旧服务是否恢复。更新前检查失败不会修改 Forkline 文件，原版本会继续运行。
- 也可以双击 `pull-latest.cmd` 拉取 `origin/main`。脚本遇到本地修改、冲突、网络或认证问题时会停止，不会强制覆盖。
- GitHub 自动生成的 `Source code (zip)` 只是源码快照，不包含 `.git`、内置 Node.js 或便携启动器，不能当作 Windows 便携版使用；需要独立桌面窗口请下载 `Forkline-Setup-*-windows-x64.exe`，需要免安装 Web 版请下载 `Forkline-v*-windows-x64-portable.zip`，然后双击其中的 `Forkline.cmd`。

```bat
npm test
```

测试使用 Node.js 内置测试框架，不需要额外安装测试依赖。系统安装 Edge、Chrome 或 Chromium 时，`npm test` 会自动加入真实浏览器性能回归；也可以单独运行：

```bat
npm run test:browser
```

### 工作区目录选择

工作区和暂存区的文件树支持点击文件夹行，一次选中或取消选中该目录下的全部当前范围改动；文件夹图标、行高亮和数量提示沿用 Windows 文件夹式视觉，部分选中时显示混合高亮。左侧箭头只负责展开/折叠；大工作区首批显示 800 个文件并按小批次追加，追加时不强制抢写滚动位置，目录很多时采用固定高度块并暂时卸载屏幕外节点，快速连续向下滚轮可以连续加载后续批次且不会因列表高度重排而弹回；选择尚未显示的文件不会触发整棵树全量渲染。

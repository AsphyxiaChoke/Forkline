# Forkline

中文 Web 端 Git 可视化管理工具。无需安装 npm 依赖，使用 Node.js 内置 HTTP 服务启动。

## 功能

- GitKraken 风格提交图谱，全部分支模式下以 `main` / `master` 为主线；本地主干优先，没有本地主干时会使用已知远端的 `main` / `master`，普通 `*/main` 本地分支不会抢主线；图谱旁的分支标签默认显示完整名称，图谱列会按标签和泳道位置自动扩宽，表头中的“全部分支”或当前分支名也不会缩写；切到单个远端分支图谱前会确认真实远端仍存在，过期时自动刷新并拒绝展示旧 tracking，切换失败会保留当前视图；顶部搜索可按提交信息、作者、分支/标签或 SHA 分词过滤，并显示命中数量和高亮；提交标题里包含特殊控制分隔符时不会导致标题、引用和父提交解析错位。
- 高频提交浏览已优化：点选当前图谱中可见的提交只原地切换选中行并刷新右侧详情，不再为一个选中样式重建整张 SVG 图谱和全部提交行；提交行点击与右键使用容器事件代理，大量历史记录不会为每一行分别创建监听器。历史完整文件读取会合并重复的提交解析和 blob 读取，文件历史 / 逐行追踪会并行准备引用与路径，同时保留无提交分支、过期远端、文件不存在、二进制和 1 MiB 上限等原有提示与边界。
- 支持命令面板：可搜索并执行常用页面跳转、同步、工作区、分支、Tag、克隆和初始化操作，危险动作保持红色标识并复用原确认流程。
- 设置页“外观”提供深色、浅色、石墨、森林、樱色和高对比 6 套皮肤，每套显示主色预览并保存到当前浏览器；顶部主题按钮会按这 6 套顺序快速切换，按钮正文显示当前皮肤，悬停提示下一套皮肤。
- 顶部支持最近仓库快速打开，会在当前浏览器记住最近打开过的真实 Git 仓库，便于在多个项目之间切换；连续打开多个仓库时只保留最后一次打开结果；有 Git 操作运行时会暂时阻止切换仓库和新的 Git 操作，避免命令执行到错误仓库或多个命令同时修改仓库状态；切换仓库期间旧工作区自动刷新、旧工作区 Diff、旧工作区按块/按行动作刷新、旧文件动作刷新、旧储藏详情/动作刷新、旧同步/远端动作刷新、旧分支/Tag/worktree/子模块/补丁动作刷新、旧历史/reset 动作刷新、旧历史重写预览、旧恢复点动作刷新、旧操作日志/运行中状态刷新、旧提交详情/文件历史/逐行追踪/比较读取不会覆盖新仓库页面；仓库相关 API 请求会携带请求发起时的仓库路径，服务端发现请求来自旧仓库时会拒绝读取或执行，写操作缺少仓库上下文也会拒绝，避免多页面、旧脚本或旧弹窗把操作打到当前新仓库；暂存全部、单文件暂存/取消暂存/丢弃、加入 `.gitignore`、冲突文件取舍、工作区 Diff 按块/按行操作、丢弃全部、创建工作树、初始化/更新/同步子模块、创建/恢复/应用/弹出/删除储藏、从储藏创建分支、提交、追加提交、拉取、变基拉取、推送、安全强推、设置或取消 upstream、应用补丁、合并、分支变基、挑选、还原、reset、恢复点恢复、引用日志恢复、修改提交信息、历史编辑，以及合并/变基/挑选/还原的继续、跳过、中止操作都会校验页面看到的当前分支和 HEAD；如果仓库正处于合并、变基、挑选或还原流程，当前分支类写操作还会校验页面看到的进行中操作快照，避免外部切换分支、移动 HEAD 或重开另一场 Git 操作后旧页面把操作执行到错误分支/错误流程；后端状态、历史、历史重写预览、工作区 Diff 和储藏详情读取会使用请求发起时的仓库路径快照，不会把两个仓库的数据混在一次响应里；打开新仓库或工作树会清空旧仓库的分支/Tag/mainline 弹窗、储藏详情、文件历史、逐行追踪、比较结果、最大化对照、历史编辑计划和右键菜单上下文；路径选择弹窗快速切换目录时只显示最后选择的目录，旧错误不会覆盖新结果。
- 仓库路径支持中文和其他 Unicode 字符：页面发送仓库上下文时会先转换为带 `v1:` 前缀的 ASCII URI 编码，避免浏览器因请求头包含非 Latin-1 字符而在 `fetch` 前直接失败；服务端严格解码新格式，并继续兼容旧版本发送的英文原始路径。
- 支持从远端 URL 或本地裸仓库克隆到指定本机目录，克隆完成后可直接打开新仓库；如果克隆期间用户又手动打开了其他仓库，旧的自动打开结果不会覆盖当前仓库。
- 支持把本机普通文件夹初始化为 Git 仓库，初始化后可直接打开；如果初始化期间用户又手动打开了其他仓库，旧的自动打开结果不会覆盖当前仓库；刚初始化且还没有提交的空仓库会显示稳定空状态，并在同步页提示先创建首个提交后再推送。
- 本地分支、远端分支、工作区状态和未暂存更改查看；左侧分支列表可按分支名或 upstream 筛选，大量本地/远端分支不会被后端静默截断，本地分支会显示 upstream、领先/落后数量和上游丢失状态。
- 右侧“分支”页支持分支整理：汇总已合并、上游丢失和长期未动分支，标出当前分支、主干分支和 worktree 占用原因，并可安全删除单个分支或批量删除已合并分支。
- 右侧“工作树”页支持 Git worktree 管理：显示每个工作树的路径、分支、HEAD、干净/有改动/失效状态，大量 worktree 不会被后端静默截断；可从任意引用创建新工作树，创建前会校验页面看到的当前分支和 HEAD，远端分支和 Tag 起点会先确认目标仍是页面看到的提交，远端分支还会确认真实远端仍指向页面看到的 SHA；可打开已有工作树、复制路径并清理失效 worktree 记录，清理前会校验页面看到的失效记录列表，避免旧页面或单项按钮清理到未确认的记录；当前分支还没有首个提交时，默认 `HEAD` 起点会提示先提交或改用已有引用。
- 右侧“子模块”页支持 Git submodule 管理：显示 `.gitmodules` 中的子模块路径、URL、目标提交、初始化状态、提交不一致和本地改动数量，大量子模块不会被后端静默截断；路径包含空格或以前导空格开头时也会按完整路径合并状态，并可初始化、更新、同步 URL、复制路径或 URL；子模块写操作会校验页面看到的当前分支、HEAD 和工作区快照，避免旧页面按外部切换后的分支记录或外部修改后的 `.gitmodules` 更新子模块。
- 右侧分支整理、工作树、子模块和操作日志刷新时，会在返回前确认当前仓库和查看引用都没有改变，避免慢返回把页面拉回旧仓库或旧分支。
- 仓库全量刷新会复用同一轮读取到的当前分支、HEAD、upstream、远端和工作区状态，并并行生成工作树、子模块、工作区和同步详情；仓库根目录没有 `.gitmodules` 时不会启动昂贵的递归 submodule helper，普通仓库刷新不再为不存在的子模块支付额外等待时间。
- 工作区自动刷新会把每个文件的内容快照纳入状态签名；即使文件仍显示为同一个 `M` 状态，继续编辑内容也会刷新文件列表和当前 Diff。页面隐藏或浏览器失去焦点时会暂停 5 秒轮询，重新聚焦或切回页面后立即检查，减少后台 Git 读取。
- 右侧“同步”页会显示当前分支 upstream、同步建议、待拉取提交、待推送提交和远端仓库配置，并提供抓取 / 拉取 / 变基拉取 / 推送 / 安全强推 / 添加远端 / 诊断连接 / 修改 URL / 删除远端入口；添加、修改、测试和删除远端支持 Git 合法的带 `/` 远端名；修改远端 URL 会确保 fetch 和一个或多个 push URL 都指向新地址，避免分离 push URL 继续推到旧仓库；抓取全部远端会校验页面看到的全部远端列表和 fetch/push URL，抓取指定远端、修改 URL 或删除远端前会校验页面看到的单个远端 fetch/push URL，避免旧页面覆盖、删除或抓取外部刚改过的远端配置；远端诊断结果会留在同步页，显示 URL、命令、中文原因、问题分类、排查步骤和可复制诊断命令。
- 同步页内置认证助手：按远端 URL 判断 SSH / HTTPS / 本地路径，列出本机 `~/.ssh` 中可见的 SSH key 文件名，检测 `ssh-agent` 和 Git Credential Manager，并提供可复制诊断命令；认证环境只在打开同步页时按需检测，不再拖慢提交历史和工作区的普通刷新，同一仓库和远端配置会复用 60 秒缓存，也可点“重新检测”立即绕过缓存。
- 同步页可为当前分支生成 Pull Request / Merge Request 创建链接，支持 GitHub、GitLab、Bitbucket 和常见 Gitea / Forgejo 网页远端；入口也在命令面板和当前分支右键菜单中，可直接打开或复制链接，远端名包含 `/` 时也会正确推断目标分支；快速切换仓库时目标分支推断会固定在请求发起时的仓库。
- 同步页的待拉取 / 待推送提交可直接点击预览文件列表和 Diff，并可最大化对照查看。
- 提交详情和提交右键菜单支持在 GitHub / GitLab / Bitbucket / Gitea 等网页远端中打开当前提交。
- 提交详情、提交右键菜单和命令面板支持补丁工作流：可把任意提交导出为 `git format-patch` 文本、复制或下载 `.patch` 文件，也可粘贴 `.patch` / `git diff` 内容并用 `git apply` 应用到工作区或直接暂存；复制或下载补丁返回前如果已经切到其他仓库，会丢弃旧结果。
- 右侧“日志”页会显示进行中的 Git 操作，并记录最近 Git 操作的成功/失败、耗时和 Git 输出摘要，便于排查哪个操作正在卡住或刚刚失败。
- 支持当前分支 upstream 管理：同步页可从已抓取的远端分支中设置 upstream 或取消 upstream；远端分支右键菜单也可直接设为当前分支 upstream。
- 支持普通推送保护：当前分支落后 upstream 或与 upstream 分叉时，Forkline 会阻止普通 `git push`，同步页显示中文保护原因，并引导先“变基拉取”或在确认改写历史时使用安全强推。
- 文件路径树状归纳，支持同层级聚合与滚动查看；工作区文件可按路径、文件名、状态和暂存状态筛选，大量改动不会被后端静默截断，未跟踪文件可从右键菜单直接加入 `.gitignore`。
- 底部工作台按“工作区 / 暂存区 / 提交编辑”三栏平行排布，工作区和暂存区拥有独立文件列表与滚动区域；中心区较窄时只在底部工作台内部横向滚动，不会撑宽提交图和整个页面。常驻“变更对照”区域已移除，底部区域仍可整体上下拖动调整高度。
- 工作区和历史提交均支持按文件 Diff 与最大化对照；工作区或暂存区文件右键“查看对照”会直接打开最大化 Diff，可在“未暂存 / 已暂存”之间切换并执行暂存、取消暂存、丢弃当前文件、按块操作和按行操作；未跟踪文本文件会按虚拟块完整展示，可只暂存选中的块。右侧提交“详情”只保留提交信息和相关操作，完整历史改动继续在“文件”页按文件查看；历史提交包含大量文件、大文件改动或长行内容时，文件清单、后续文件 Diff 和长行尾部内容仍可完整查看；merge 提交详情会按第一父提交展示本次合并带入的文件变化；历史、同步和比较里的单文件对照会精确匹配路径，避免 `foo.txt` 误命中 `dir/foo.txt`。
- 支持常驻浮窗式工作区文件编辑：双击工作区文件即可打开；浮窗打开后仍可操作后方页面，单击其他工作区文件会在原浮窗位置切换内容，有未保存修改时先中文确认。普通文件左侧只读显示暂存区版本，右侧编辑工作区版本，未跟踪文件左侧为空；冲突文件因暂存区没有单一版本，会改用单栏工作区编辑，避免大型冲突文件被无意义的空左栏、同步滚动和差异连线拖慢。普通文件双栏带行号、旧红新绿差异强调、常见代码语法高亮和查找替换，冲突文件单栏继续保留行号、高亮、查找替换和保存。中间操作改为按块“暂存”，在右侧选中代码后可通过右键菜单暂存所选行，或确认后还原选区所在的整个未暂存改动块；编辑器存在未保存内容时会先要求保存，避免 Git 操作覆盖内存中的编辑。桌面浮窗默认约 `1180×760`，可拖动标题栏空白区域移动并通过右下角手柄调节大小，移动和缩放限制在当前视口内；窄屏保持近全屏并禁用自由拖动和缩放。中间操作区桌面固定为 `48px`、窄屏为 `40px`，左右代码栏各自保留横向滚动；支持 `Ctrl+F`、`Ctrl+H`、`Ctrl+S`。保存、按块暂存或右键 Git 操作后编辑器继续保持打开并重新加载最新对照；仓库内不超过 1 MiB 的 UTF-8、UTF-8 BOM、GBK 和 GB18030 普通文本文件会保持原编码及 CRLF / LF / CR 换行，文件被外部程序修改时拒绝旧内容覆盖，二进制、符号链接、目录、`.git` 内部文件和越界路径不开放编辑。CodeMirror、diff-match-patch、iconv-lite 及其运行依赖 safer-buffer 均随仓库提供，无需额外执行 `npm install`。
- 右侧提交“文件”页的变更文件支持双击打开同一套浮窗式完整代码对照：左栏显示该提交第一父提交中的完整文件，右栏显示当前提交中的完整文件，并在完整上下文中标出新增、删除和修改；新增、删除、重命名、根提交和 merge 提交均按第一父提交语义处理。提交包含大量变更文件时，单击文件只更新右侧 Diff，文件列表会保持原滚动位置和当前节点，随后仍可原地双击打开完整对照。打开历史完整对照后，右侧大 Diff 会暂时卸载并显示轻量提示，已移除的底部常驻对照也不会在隐藏区域重复渲染；浮窗打开期间继续选择其他提交文件不会重新生成重型预览，关闭浮窗后恢复当前选中文件的右侧 Diff。历史提交模式严格只读，保留行号、语法高亮、差异着色、连接线、同步滚动和查找，隐藏保存、替换、暂存及编辑器 Git 右键操作；只读模式不启用 MergeView 的强制垂直行对齐，避免特定文件触发持续布局计算，工作区编辑器仍保留行对齐和按块暂存按钮；读取仍遵守 1 MiB、普通文本和 UTF-8 / GBK / GB18030 边界。
- 历史文件右侧 Diff 和最大化 Diff 对大差异采用分批渲染：首批只创建前 `1000` 行，点击“继续加载”后按 `2000 / 4000 / 8000...` 逐步扩展，完整 Diff 数据不会被截断。切换历史文件会重置右侧预览批次，关闭最大化窗口会立即清空其中已渲染的行，避免隐藏窗口继续占用大量页面节点。
- 文件编辑器中间的“暂存”按当前看到的独立改动块执行；每个按钮会按暂存区和工作区两侧改动范围的联合高度垂直居中，正对整个视觉块。相邻修改即使在普通 Git Diff 中会因上下文合并成一个大块，点击其中一个按钮也只暂存对应的视觉块，不会把同文件其他块一起暂存。当工作区存在暂存区没有的新增行时，暂存区会显示与新增内容等高的斜纹占位；删除行则在工作区一侧对称显示占位，左右代码始终保持对应位置对齐。
- 支持文件历史：工作区文件右键或提交文件面板可查看单个文件的 `git log --follow` 历史，并跳转到相关提交或该文件的历史改动；历史记录中的提交即使不在当前图谱加载范围内，也可在右侧打开详情并使用提交操作；提交标题里包含内部记录分隔符时不会让该提交从文件历史中消失，远端分支引用过期时会先刷新并拒绝展示旧 tracking 数据；快速切换文件或仓库时只显示最后选择的文件历史。
- 支持逐行追踪：工作区文件右键或提交文件面板可查看 `git blame` 结果，定位每一行对应的提交、作者、时间和摘要；行对应的提交即使不在当前图谱加载范围内，也可在右侧打开详情并使用提交操作；远端分支引用过期时会先刷新并拒绝展示旧 tracking 数据；快速切换文件或仓库时只显示最后选择的逐行追踪。
- 可拖拽左侧栏、右侧栏和底部工作台高度；工作区、暂存区、提交编辑三列保持统一布局，不再单独拖动文件列表宽度或提交框高度。窗口临时缩窄时左右栏只会按可用空间压缩，重新放大后会自动恢复用户保存的宽度。电脑屏幕旋转为竖屏且视口宽度不超过 `1600px` 时，左侧分支栏仍与图谱并排并保留拖动，右侧详情会停靠到图谱下方整行，避免三栏横向挤压。

- 仓库存在未完成的 merge、rebase、cherry-pick 或 revert 时，本地分支切换和远端分支签出会在任何储藏、`reset --hard` 或 `git clean` 之前直接拒绝，并提示先继续或中止当前操作；这避免“强制签出”先丢弃冲突处理内容，随后又被 Git 拒绝切换而留下半完成状态。
- “丢弃全部”和本地/远端“强制签出”不会静默跨越子模块仓库边界。已初始化子模块只要存在未提交文件、冲突，或 HEAD 与父仓库记录的 gitlink 不一致，后端就会在父仓库执行 `reset --hard` / `git clean` 前拒绝并列出路径；这样既避免默认配置下误报“全部已丢弃”但子模块仍脏，也避免 `submodule.recurse=true` 时意外删除子模块本地提交和已跟踪修改。工作区中的子模块路径也不会被父仓库当作普通文件执行“丢弃”：后端识别到 gitlink 后会直接拒绝，并提示进入子模块单独提交、储藏或还原，避免默认配置下假成功，也避免递归配置清空子模块内部修改。已暂存区的 gitlink 同样不能执行“丢弃已暂存修改”；Forkline 会同时检查索引和 `HEAD`，包括已暂存删除的子模块，并提示使用“取消暂存”只撤销父仓库 gitlink 暂存。硬重置到提交、恢复到 Forkline 恢复点和恢复引用日志记录也会在各自的 `reset --hard` 前执行相同检查，即使 `submodule.<name>.ignore=dirty` 让父仓库状态看起来干净也不会跨仓库删除内容；软重置和混合重置不改子模块工作区，仍可正常执行。
- 支持比较任意两个引用：可从分支右键菜单比较当前分支与本地/远端分支，也可在右侧“比较”页直接输入本地分支、远端分支、Tag 或提交 SHA；比较目标如果是过期远端分支会自动刷新并拒绝使用本地旧 tracking；快速切换比较目标或仓库时只显示最后选择的比较结果；比较结果会显示两边独有提交、文件变化和可最大化 Diff。
- 支持创建 Tag、标签列表、复制/查看 Tag、删除本地 Tag、推送 Tag、删除远端 Tag；创建 Tag 会先确认目标提交仍存在，避免过期提交详情透出 Git 原始错误；大量本地 Tag 不会被后端静默截断，Tag 说明里包含 Tab 时也会完整显示，相关动作也集成在 Tag 右键菜单中。
- 支持合并冲突工作流：冲突时工作区会显示继续 / 中止合并；冲突文件可一键使用当前版本或对方版本解决并暂存；继续或中止会校验页面看到的是同一次合并和同一份工作区，避免旧页面中止外部新开始的合并，或丢掉外部刚写入的冲突解决内容。
- 支持从分支右键菜单把当前分支变基到目标分支；变基冲突时工作区会显示继续 / 跳过 / 中止变基；这些操作会校验页面看到的是同一次变基和同一份工作区。
- 支持在提交右键菜单和提交详情中挑选提交到当前分支；merge 提交会先选择主线；挑选前会校验工作区快照，避免旧页面把新提交叠到外部刚出现的改动上；冲突时工作区会显示继续 / 跳过 / 中止挑选；继续、跳过或中止会校验页面看到的是同一次挑选和同一份工作区。
- 支持在提交右键菜单和提交详情中还原提交；merge 提交会先选择主线；还原前会校验工作区快照，避免旧页面把反向提交叠到外部刚出现的改动上；支持软 / 混合 / 硬重置到指定提交，并在按钮旁标注对应 Git 指令；reset 前会校验页面看到的工作区快照，避免旧页面把外部刚写入的改动重置掉；硬重置还会独立检查子模块内部状态，避免父仓库状态忽略子模块修改时静默删除独立仓库内容。
- 支持修改提交信息：最新提交使用 amend，历史提交使用 rebase reword；修改旧提交信息时会拦截包含 merge 提交的重放范围，避免把分支拓扑展平；提交详情和右键菜单支持把非 merge 提交压缩进父提交、修补进父提交或从历史中丢弃，执行前会先展开历史编辑计划并显示影响范围、阻塞原因和恢复点提示；也支持把多条 squash / fixup / drop / reword 动作加入历史编辑队列，队列项可直接改动作、填写新的提交摘要/正文并调整显示顺序，统一预检后一次执行。
- 支持自动恢复点：追加提交、变基拉取、分支变基、历史编辑和重置前会自动创建隐藏恢复引用，同一秒内连续执行同类危险操作也会保留多个恢复点而不是覆盖；右侧“恢复点”页可搜索、按分支/动作筛选、恢复、删除、批量清理，或按“保留最近 N 天 / 每个分支保留 N 个”策略清理；恢复点对应提交标题里包含 Tab 时也会完整参与搜索；保留策略会记住到当前浏览器，清理前会展开候选恢复点，执行时会校验候选列表未变化。
- 支持引用日志恢复：右侧“恢复点”页打开时才会按需读取 HEAD reflog，可查看历史位置对应提交、从 reflog 创建 Forkline 恢复点，或在工作区干净时恢复到某条引用日志；支持手动刷新，仓库、分支或 HEAD 变化后旧结果不会覆盖当前页面；相关动作也集成在 reflog 行右键菜单中，reflog 说明包含内部控制分隔符时不会把作者和时间解析错位。

## 启动

```bat
start.cmd
```

启动所需的 `iconv-lite`、`safer-buffer` 等运行文件都随仓库提供，不需要执行 `npm install`。如果旧副本启动时提示 `Cannot find module 'safer-buffer'`，请重新拉取或下载最新版本后再运行 `start.cmd`。

需要快速更新项目时，先确认当前位于 `main` 分支，再双击根目录的 `pull-latest.cmd`。脚本会在当前项目目录执行 `git pull --rebase origin main`，成功后显示最新提交；如果存在需要先处理的本地改动、变基冲突、网络或认证问题，脚本会停止并保留错误信息，不会强制覆盖文件。

打开：

```text
http://127.0.0.1:5177
```

默认显示示例数据。顶部输入本机 Git 仓库路径后点击 `打开`，即可读取真实仓库。

成功打开真实仓库后，Forkline 会把仓库路径保存到当前浏览器的“最近仓库”下拉框中。这个记录只存在浏览器本地存储里，清除最近仓库不会删除任何本地 Git 仓库。

顶部“克隆”会执行 `git clone <来源> <保存到>`。目标必须是本机绝对路径；如果目标文件夹已经存在且不是空文件夹，Forkline 会拒绝覆盖。

顶部“初始化”会执行 `git init <文件夹>`。文件夹必须是本机绝对路径；如果目标不存在，Forkline 会创建这个文件夹；如果目标已经是 Git 仓库，会中文拒绝重复初始化。普通非 Git 文件夹可以直接初始化，已有文件会保留在工作区中等待第一次提交。

本地静态资源响应使用 `Cache-Control: no-store`，开发时刷新页面会直接拿到最新的 `app.js` / `styles.css`。静态文件服务只允许读取 `public/` 内的资源，带编码反斜杠的目录穿越请求会返回 `403`。

## 注意

真实仓库模式下的写入操作会先弹窗确认，再由本地 Node 服务执行 Git 命令。修改历史提交信息和变基都会重写相关 SHA，工作区不干净时会被阻止。本地 API 的 POST 请求只接受 `application/json`，避免外部网页用简单 `text/plain` 请求绕过前端确认触发克隆、初始化或 Git 写操作。当前分支类写操作会带上页面看到的分支名和 HEAD；如果仓库还有合并、变基、挑选或还原进行中，也会带上页面看到的 Git 操作快照；如果仓库被外部命令切到其他分支、当前分支 HEAD 已经变化，或进行中的 Git 操作已经换成另一场，后端会拒绝旧页面请求并提示刷新后重试。文件暂存/丢弃、加入 `.gitignore`、工作区 Diff 按块/按行、暂存全部、丢弃全部、拉取、变基拉取、本地/远端分支签出、提交、追加提交、创建/应用/弹出储藏、从储藏创建分支、合并、挑选、还原、reset、应用补丁和子模块初始化/更新/同步还会校验页面看到的文件或工作区快照，避免同一分支上的文件内容、暂存状态或 `.gitignore` / `.gitmodules` 已被编辑器/外部 Git 改过后，旧页面继续操作新的内容；暂存重命名文件这类 pathspec 状态和全量状态显示不同的场景，会回退到全量状态校验，避免把合法操作误判成过期。合并、变基、挑选和还原的继续/跳过/中止会同时校验页面看到的 Git 操作快照和工作区快照，避免外部已经结束旧操作并开始新操作后，旧页面继续/中止新的冲突流程，也避免外部刚改过冲突文件后旧页面继续提交或中止丢弃这些新内容。以本地或远端分支为目标的签出、合并、变基、新建分支和创建工作树还会校验页面看到的目标分支 SHA，远端分支还会校验真实远端 SHA，设置 upstream 会校验页面看到的目标远端分支 SHA 和真实远端 SHA，避免外部移动同名分支后旧页面继续使用新提交或把当前分支跟踪到已变化的远端分支。拉取、变基拉取、推送、安全强推和取消 upstream 还会校验页面看到的 upstream 及相关远端 URL，避免旧页面把同步操作打到外部刚改过的远端；安全强推还会校验并绑定页面看到的 upstream 提交，避免旧页面在外部 fetch 更新 tracking 后覆盖别人新推送的提交；拉取和变基拉取还会同时校验工作区快照，避免旧页面在外部新改动旁移动当前分支。旧脚本或旧页面缺少这份分支快照时，后端同样会拒绝执行本地/远端分支签出、新建分支、文件暂存/丢弃、加入 `.gitignore`、工作区 Diff 按块/按行、创建工作树、子模块写操作、储藏写操作、upstream 设置、应用补丁、合并、reset、恢复点/引用日志恢复、挑选、还原、历史编辑、继续/跳过/中止进行中 Git 操作等高风险动作；仓库已有进行中 Git 操作时，缺少操作快照的当前分支类写操作也会被拒绝。

从引用日志创建恢复点也会校验页面看到的当前分支和 HEAD，避免旧页面在外部切换分支后把恢复点创建到错误的分支目录下。

抓取、拉取和推送完成后，Forkline 会显示同步摘要。摘要会说明当前分支对应的 upstream、本地领先/落后数量如何变化，以及这次远端引用新增、更新或删除了什么。

推送当前分支时，如果已经设置 upstream，Forkline 会执行普通 `git push`；如果没有 upstream，会选择 `origin` 或第一个可用远端执行 `git push -u <远端> <当前分支>`。推送前会校验页面看到的 upstream 和对应远端 URL；没有 upstream 时也会校验页面看到的默认推送远端，避免外部刚修改 `origin` 后旧页面把提交推到新的远端。如果当前分支还没有任何提交，普通推送和安全强推都会被阻止，并提示先创建首个提交。删除远端分支会执行带显式 lease 的 `git push --force-with-lease=refs/heads/<分支>:<确认的远端SHA> <远端> --delete <分支>`，只删除远端仓库中的分支，不会删除本地分支；后端会拒绝删除 `main` / `master` / `develop` / `dev` / `trunk` 这类远端主干/长期分支；删除前会同时校验页面看到的远端 URL、tracking SHA、当前本地 tracking SHA 和真实远端 SHA，实际删除也会原子绑定确认的远端 SHA，避免校验后别人刚推送的新提交被旧删除操作移除，或在 `origin` 被外部改到另一个仓库后删到错误远端；如果远端分支已被别人删除但本地列表还没刷新，Forkline 会自动抓取并清理过期的远端跟踪引用。

同步页里的远端仓库管理对应 `git remote add`、`git remote set-url`、`git remote remove`、`git fetch --all --prune`、`git fetch <远端> --prune` 和 `git ls-remote --heads <远端>`。删除远端只会移除当前本地仓库的远端配置，不会删除 GitHub 或服务器上的仓库。抓取全部远端会携带页面看到的远端列表和 fetch/push URL；修改 URL、删除远端和抓取指定远端会携带页面看到的单个远端 fetch URL 和完整 push URL 列表；如果远端 URL 已经被外部命令改过，Forkline 会拒绝旧页面请求并提示刷新，避免旧页面覆盖、删除或抓取新的远端配置。修改 URL 时，如果远端配置了多个 `pushurl`，会清除旧 push URL 并写入新的唯一地址。“诊断连接”只读取远端分支列表，用来确认远端 URL、网络和认证是否可用，不会写入本地引用；诊断结果会在同步页保留，失败时会按 SSH key、HTTPS token、仓库权限、DNS/代理、证书或 URL/本地路径分类，给出中文排查步骤和可复制命令。本地路径远端不存在或不是 Git 仓库时，错误提示会直接显示具体路径，包含 `MissingBare.git` 这类相对裸仓库路径。

同步页的认证助手只读取认证环境摘要，不读取或显示私钥内容。SSH key 清单只展示文件名、是否有公钥/私钥配对和更新时间；`ssh-agent` 检测执行 `ssh-add -l`，HTTPS 凭据检测会尝试 `git credential-manager version` / `git credential-manager-core --version`。这些本机探测由独立的 `/api/auth-diagnostics` 接口按需执行，接口要求当前仓库路径上下文，并按规范化仓库路径和完整 fetch/push URL 缓存 60 秒；修改远端配置会使用新缓存键，“重新检测”会显式绕过缓存。真正的远端权限仍以“诊断连接”的 `git ls-remote --heads <远端>` 结果为准。

同步页的 PR/MR 链接只根据当前本地分支和已识别的网页远端生成，不会创建远端分支或提交网页表单。Forkline 会优先使用当前分支的 upstream 作为目标分支；如果 upstream 和当前分支同名，则回退到 `main` / `master` / `develop` / `dev` / `trunk` 等主干分支。本地路径远端不会生成 PR/MR 链接。

设置 upstream 会执行 `git branch --set-upstream-to=<远端分支> <当前分支>`；取消 upstream 会执行 `git branch --unset-upstream <当前分支>`。Forkline 只允许给已经有提交的当前本地分支设置已抓取到且远端仍存在的分支，避免误把不存在的引用写进配置；设置或取消前也会校验页面看到的当前分支和 HEAD，设置 upstream 还会校验目标远端分支 SHA、真实远端 SHA 和目标远端 URL，避免旧页面把 upstream 写到外部切换后的分支、外部更新后的远端分支或外部改过 URL 的远端。如果本地列表残留了已删除或已推进的远端分支，会自动刷新并拒绝设置。从远端分支签出时，如果本地同名分支已经存在但没有 upstream，会自动把它设置为所选远端分支；如果已有其他 upstream，会保留现有设置并在结果中说明。

安全强推会执行带显式 lease 的 `git push --force-with-lease=refs/heads/<分支>:<页面看到的upstream提交> <远端> HEAD:<分支>`，用于 rebase、squash、amend 等改写历史之后更新远端分支。它不会使用裸 `--force`；如果页面打开后外部 fetch 更新了本地 tracking，或远端分支在确认后又变化，后端/Git 会拒绝这次强推。后端会拒绝把安全强推打到 `main` / `master` / `develop` / `dev` / `trunk` 这类远端主干/长期分支。

普通推送前，Forkline 会检查当前分支与 upstream 的领先/落后关系。如果本地落后远端，或本地领先同时落后形成分叉，普通推送会被保护拦截，避免非快进推送失败或误覆盖协作历史。如果当前分支名和 upstream 指向的远端主干/长期分支名不一致，后端也会拒绝普通推送，避免 `push.default=upstream` 这类配置把普通分支推到 `origin/main`。同步页会显示待拉取/待推送提交，方便先判断应该拉取、变基拉取还是安全强推。

“拉取”执行 `git pull --ff-only`，只允许快进，避免偷偷生成 merge commit。“变基拉取”执行 `git pull --rebase`，会先拉取 upstream，再把本地未推送提交重放到远端提交之后；这些本地提交的 SHA 可能改变。两者执行前都会校验页面看到的工作区快照，如果外部编辑器或 Git 命令已经产生新改动，会提示刷新后重新操作。遇到冲突时，工作区会进入变基冲突流程，并显示继续 / 跳过 / 中止变基。

推送 Tag 会执行 `git push <远端> refs/tags/<tag>:refs/tags/<tag>`；如果远端已经有完全相同的 Tag，会提示无需重复推送。删除远端 Tag 会先确认远端仍存在该 Tag，再执行带显式 lease 的 `git push --force-with-lease=refs/tags/<tag>:<确认的远端对象SHA> <远端> :refs/tags/<tag>`，不会删除本地 Tag。本地删除 Tag 使用 `git tag -d <tag>`，不会影响远端 Tag。推送、删除本地 Tag 或删除远端 Tag 前，后端会校验页面选中时看到的 Tag 对象 SHA；如果本地或远端同名 Tag 已经变成另一个对象，会拒绝旧页面请求，实际删除也会原子绑定确认的远端对象 SHA，避免校验后别人刚移动的新 Tag 被旧删除操作移除。推送或删除远端 Tag 时还会校验页面看到的远端 URL，避免外部刚修改 `origin` 后旧页面把 Tag 推到或删到新的远端。推送或删除远端 Tag 失败时，Forkline 会按实际远端名显示认证、路径或网络提示；如果远端可访问但该 Tag 已不存在，会提示刷新 Tag 列表后重新选择；如果远端已有同名 Tag 且 Git 拒绝覆盖，会提示先确认是否删除远端 Tag 或改用新 Tag 名。

对 merge 提交执行挑选或还原时，Forkline 会要求选择主线，对应 Git 的 `-m <父提交编号>`。通常父提交 1 是执行合并时所在的分支方向，父提交 2 是被合并进来的分支方向。

如果 Git 提示 `index.lock`，Forkline 会在中文提示里显示刚才执行的操作、锁文件路径/时间，以及能检测到的 Git 进程。`index.lock` 本身不记录具体命令；确认没有 Git 或编辑器正在操作仓库后，才能删除这个锁文件重试。

合并分支时如果出现冲突，工作区会标出冲突文件，并显示“继续合并 / 中止合并”。冲突文件右键菜单和底部 Diff 面板可执行“使用当前版本 / 使用对方版本”，对应 `git checkout --ours -- <文件>` / `git checkout --theirs -- <文件>` 后自动 `git add <文件>`；解决并暂存后继续，不想保留这次合并则中止。继续或中止前会比较页面看到的 `MERGE_HEAD` 等操作快照和工作区快照，如果外部命令已经中止旧合并并开始另一场合并，或外部编辑器已经改过冲突文件，会拒绝旧页面请求。变基、挑选、还原冲突也复用同一套文件级解决入口；仓库处于这些进行中操作时，普通提交、reset、文件操作等当前分支写操作也会校验对应 Git 控制文件快照，避免旧页面绕过继续/中止按钮操作到新的冲突流程。

分支右键菜单里的“与当前分支比较”会读取 `git rev-list --left-right --count <当前分支>...<目标分支>`，并用 `git diff <当前分支>...<目标分支>` 展示目标分支相对共同祖先带来的文件变化。这个比较支持本地分支和已抓取到且远端仍存在的远端分支；如果本地还残留已删除远端分支的 tracking 引用，会自动刷新并提示重新选择。当前分支还没有首个提交时，需要先提交一次或手动选择两个已有提交的引用。

补丁导出会执行 `git format-patch -1 <提交> --stdout`，适合把单个提交发给别人或跨仓库搬运改动。应用补丁会先校验页面看到的当前分支和 HEAD，再执行 `git apply --check` 预检；勾选“应用后暂存”时使用 `git apply --index`，不勾选时只写入工作区。如果当前分支内容和补丁生成时不一致，Git 会拒绝应用，Forkline 会显示中文原因。

右侧“分支”页的整理列表会读取本地分支最后提交、upstream 状态和 `git branch --merged HEAD`。单个删除和“删除已合并”都执行安全删除 `git branch -d <分支>`；如果分支还没有完全合并，Git 会阻止删除。Forkline 默认保护当前分支和 `main` / `master` / `develop` / `dev` / `trunk` 这类主干分支，后端也会拒绝删除或重命名这些主干分支，并会禁用被其他 worktree 占用的分支。如果分支已经被外部 Git 命令删除、同名分支已经移动到另一个提交，或重命名前当前仓库已经切到其他分支，删除或重命名时会提示刷新分支列表后重新选择。

右侧“工作树”页读取 `git worktree list --porcelain`，并对仍存在的工作树补充 `git status --short` 摘要。创建工作树会执行 `git worktree add <目标文件夹> <起点引用>`；填写新分支名时会执行 `git worktree add -b <新分支> <目标文件夹> <起点引用>`。目标必须是本机绝对路径，目标文件夹不存在或为空；Forkline 不会覆盖已有文件。创建前会校验页面看到的当前分支和 HEAD，避免旧页面的 `HEAD` 起点在外部切换分支后从错误提交创建工作树。当前分支还没有首个提交时，不能用默认 `HEAD` 或当前无提交分支名作为起点创建工作树，需要先创建首个提交，或把起点改成已有本地分支、Tag 或提交 SHA。如果起点是已抓取的远端分支或本地 Tag，Forkline 会先确认目标仍存在且仍指向页面看到的对象；远端分支还会确认真实远端 SHA 没有变化；过期时会拒绝创建，远端分支过期还会自动刷新远端分支列表。清理失效记录执行 `git worktree prune --verbose`，只清理 Git 元数据，不删除仍存在的工作区文件；执行前会校验页面看到的失效记录快照，单项清理只允许当前确实只有这一条失效记录，多条失效记录需要使用“清理失效”一次确认全部。

右侧“子模块”页读取 `.gitmodules` 和 `git submodule status --recursive`。读取 `.gitmodules` 时使用 `git config -z` 保留路径值里的前导空格，并用完整配置路径匹配状态行。初始化或更新会执行 `git submodule update --init --recursive`；单个子模块更新会追加 `-- <路径>`，路径参数同样保留前导空格。这个命令会把子模块签出到父仓库当前记录的提交，不会自动切到子模块远端最新提交；如果要跟踪最新提交，需要先在子模块里更新并在父仓库提交新的 gitlink。同步 URL 会执行 `git submodule sync --recursive`，用于把 `.gitmodules` 中的 URL 写回本地子模块配置。初始化、更新或同步前会校验页面看到的当前分支、HEAD 和工作区快照，避免旧页面按外部切换后的分支记录或外部修改后的 `.gitmodules` 改动子模块工作区或配置。

文件历史会执行 `git log --follow --find-renames <引用> -- <文件>`，用于追踪单个文件的新增、修改、删除和重命名记录。Forkline 只接受仓库内相对路径，避免读取仓库外文件。当前分支还没有首个提交时，不能用当前 `HEAD` 查看文件历史，需要先创建首个提交，或手动选择已有分支、Tag 或提交 SHA。如果引用是已抓取的远端分支，Forkline 会先确认真实远端分支仍存在；过期时会自动刷新远端分支列表并拒绝读取。文件历史解析会按提交头行识别记录，不依赖可出现在提交标题里的控制分隔符。

工作区 Diff 的“未暂存 / 已暂存”切换会分别读取 `git diff` 和 `git diff --cached`。当同一个文件既有已暂存改动又有未暂存改动时，可以切到对应视图查看和操作，文件列表会用“未暂存 / 已暂存 / 未跟踪”区分所在区域。“暂存此块 / 取消暂存此块 / 丢弃此块”会重新读取当前文件的真实 Git diff，再用 `git apply` 只应用选中的 hunk。文件级和 Diff 细粒度写操作也会校验页面看到的当前分支、HEAD 和文件快照，避免外部切换分支后旧页面误暂存/误丢弃当前分支内容，也避免同一分支文件内容被编辑器改过后旧 hunk 或旧行选择作用到新的内容。内容本身以 `++` 或 `--` 开头导致 Diff 行显示成 `+++...` / `---...` 时，Forkline 会按真实新增/删除内容行解析，仍可正常按行选择。未跟踪文本文件会按 40 行左右生成虚拟块，并完整保留文件内容，不会只显示前 420 行；空的未跟踪文件只显示文件元信息，不会生成假的空白新增行；没有末尾换行的未跟踪文件按块或按行暂存时不会被补上换行，按行只暂存非末行时也不会把末行的无换行标记误带到暂存区；UTF-8 BOM 会被保留；对 `.gitattributes` 标记为 `-text` 的 CRLF 文件不会把 `CRLF` 改成 `LF`；文件名前导空格会被保留；无法严格按 UTF-8 解码的未跟踪文件不会开放虚拟块/行暂存，避免把原始字节转坏。未跟踪文件的块级丢弃不开放，需要在编辑器里修改文件内容。当前分支还没有首个提交时，“丢弃全部”会跳过不存在的 `HEAD`，直接清理索引和未跟踪文件。

未跟踪文件右键菜单里的“加入 .gitignore / 忽略所在目录”只会向仓库根目录的 `.gitignore` 追加规则，例如 `/tmp.log` 或 `/dist/`，不会删除本地文件，也不会自动暂存 `.gitignore`。执行前会校验页面看到的工作区快照，避免旧页面在外部新增文件或编辑 `.gitignore` 后继续写入旧忽略规则。已跟踪文件不会因为加入 `.gitignore` 自动停止跟踪，需要先从 Git 索引中移除后才能忽略。

逐行追踪会执行 `git blame --line-porcelain <引用> -- <文件>`，右侧“逐行”页会显示行号、提交短 SHA、作者和代码内容。当前分支还没有首个提交时，不能用当前 `HEAD` 做逐行追踪，需要先创建首个提交，或手动选择已有分支、Tag 或提交 SHA。如果引用是已抓取的远端分支，Forkline 会先确认真实远端分支仍存在；过期时会自动刷新远端分支列表并拒绝读取。大文件会限制返回前 600 行，避免浏览器卡顿；Forkline 同样只接受仓库内相对路径。

变基当前分支到其他分支时，Forkline 会执行 `git rebase <目标分支>`。如果目标是已抓取的远端分支，执行前会先确认真实远端分支仍存在；过期时会自动刷新远端分支列表并拒绝变基。这会重写当前分支中被重放提交的 SHA；如果这些提交已经推给别人协作，应先确认团队是否允许。变基冲突时，工作区会标出冲突文件，并显示“继续变基 / 跳过变基 / 中止变基”。解决冲突并暂存后继续；不想保留当前冲突提交可跳过；想回到变基前状态则中止。

历史编辑里的“压缩进父提交 / 修补进父提交 / 丢弃此提交”对应 `git rebase -i` 的 `squash`、`fixup`、`drop`。点击后 Forkline 会先在提交详情中展开计划，显示当前分支、目标提交、父提交、重放范围、影响提交数量和阻塞原因；确认执行后才会重写当前分支历史 SHA。Forkline 会要求工作区干净，并暂时拒绝自动编辑包含 merge 提交的历史段，避免破坏分支拓扑。

历史编辑队列可以从提交详情或提交右键菜单把多条提交加入同一个队列。队列项可以直接改为 squash、fixup、drop 或 reword，也可以上移/下移整理显示顺序；reword 队列项会显示新的提交摘要和正文输入框。Forkline 会统一预检队列组合，并在预览区显示按当前分支历史生成的实际执行顺序。预检会拦截 merge 提交、脏工作区、重复提交、reword 与 squash/fixup 混用、以及“前一条提交会被丢弃但后一条还要 squash/fixup”的危险组合；执行队列前同样会创建恢复点。

执行追加提交、变基拉取、分支变基、修改提交信息、历史编辑或 reset 前，Forkline 会在 `refs/forkline/recovery/...` 下创建隐藏恢复点，不会污染普通分支列表。同一秒内同一分支连续创建同类恢复点时，后续恢复点会追加 `-2`、`-3` 这类后缀，避免覆盖更早的恢复点。追加提交只会读取当前仓库真实 `HEAD` 的提交信息；当前分支还没有首个提交时没有可追加目标，入口会禁用，后端也会中文拒绝。当前分支还没有首个提交时，reset 到已有提交会继续执行，但因为没有重置前 `HEAD` 可保存，结果会说明本次无法创建恢复点；reset 前会校验页面看到的工作区快照，避免旧页面把外部刚写入的工作区内容重置掉。右侧“恢复点”页可以搜索、按分支/动作筛选、批量清理，也可以按“保留最近 N 天 / 每个分支保留 N 个”策略清理旧恢复点，或执行 `git reset --hard <恢复点>` 回到对应提交；恢复前 Forkline 会再创建一个新的恢复点，若当前分支还没有首个提交则会继续恢复并说明无法保存恢复前位置。恢复页面选中的恢复点时会校验页面看到的当前分支、HEAD 和恢复点提交 SHA；如果分支已被外部切换、HEAD 已移动或同一个恢复点 ref 已经指向另一个提交，会拒绝旧页面请求，避免把当前分支硬重置到错误提交。删除恢复点时，后端会校验页面看到的提交 SHA，避免删错恢复点。恢复点保留策略会保存到当前浏览器，策略卡会在清理前展示将删除的候选恢复点；执行清理时会提交候选 ref 和 SHA，后端重新计算后必须与候选完全一致，否则拒绝旧页面请求，避免误删刚产生的恢复点。恢复点只保存提交位置，不保存未提交的工作区改动。

同一页的“引用日志”通过独立 `/api/reflog` 按需执行 `git log -g HEAD`，用于找回曾经被 reset、checkout、rebase 或 amend 移走的 HEAD 位置；普通 `/api/state` 不再固定读取和传输这 80 条记录。前端按仓库路径、当前分支和 HEAD 保存结果，切仓库或 HEAD 变化会自动重新读取，也可点击“刷新”。点击“创建恢复点”只会把那条 reflog 提交保存到 `refs/forkline/recovery/...`；点击“恢复到此处”会执行 `git reset --hard <提交>`，因此要求当前在本地分支且工作区干净，执行前也会先创建一个恢复前恢复点，并校验页面看到的当前分支和 HEAD 没有被外部改过。

右侧“日志”页显示当前正在执行的 Forkline 操作，以及本地服务启动后的最近 Git 操作。它会记录操作名称、动作类型、成功/失败、耗时和 Git 输出摘要；刷新页面不会清空日志，重启本地服务后日志会重新开始。

还原提交时如果出现冲突，工作区会标出冲突文件，并显示“继续还原 / 中止还原”。解决冲突并暂存后继续；不想保留这次还原则中止。如果还原会覆盖当前工作区的本地修改，Forkline 会提示先提交、储藏或丢弃这些修改，不再显示签出分支才相关的建议。

挑选提交时如果出现冲突，工作区会标出冲突文件，并显示“继续挑选 / 跳过挑选 / 中止挑选”。解决冲突并暂存后继续；不想保留当前提交可跳过，不想继续这次挑选可中止。如果挑选会覆盖当前工作区的本地修改，也会提示先提交、储藏或丢弃这些修改。

## Git 储藏

储藏相当于把当前未提交的改动临时收进一个 Git stash。储藏后，文件会从工作区列表里消失，这是正常行为；这些改动没有丢，会出现在右侧“储藏”页，可以查看 Diff、应用、弹出、删除，或执行 `git stash branch <分支> <储藏>` 从这条储藏创建新分支。成功从储藏创建分支后，Git 会切到新分支并移除对应储藏。当前分支还没有首个提交时，Git 不能创建储藏，也不能“储藏并签出”；Forkline 会提示先提交一次，或使用“丢弃全部 / 强制签出”清理未跟踪文件。

如果同一路径同时存在“已暂存删除/重命名旧路径”和“未跟踪重建”，Forkline 会拒绝储藏、储藏所选和储藏并签出，并提示先取消暂存删除或把重建文件改名。这个保护是为了避免 `git stash -u` 生成 Git 自己也无法正常查看或应用的 duplicate entries 储藏。如果仓库里已经有旧版本或手动 Git 生成的同类坏储藏，查看、应用或弹出失败时会显示中文原因，通常需要确认不再需要后删除该储藏。

当本次储藏范围包含子模块路径时，Forkline 会在执行前拒绝。Git stash 不能可靠保存子模块内部文件，也可能在储藏里记录了 gitlink，却在 `stash apply` / `stash pop` 时不恢复；其中 `pop` 仍可能删除原储藏。对旧版 Forkline 或命令行已经生成的这类 gitlink 储藏，应用、弹出、从储藏创建分支和恢复签出储藏都会先阻止，原储藏保持不变，并提示到子模块中确认目标提交后手动更新父仓库指针。只储藏其他普通父仓库文件仍可正常执行。

“储藏并签出”还会读取真实子模块状态。即使 `submodule.<name>.ignore=dirty` 让父仓库工作区看不到子模块内部修改，本地和远端签出也会在创建 stash 前拒绝，避免父仓库文件已经移入储藏、分支却因子模块更新失败而没有切换。手动储藏普通父仓库文件不受这项签出保护影响，子模块内部修改仍保留在原子模块中。

储藏所选会先确认所选文件确实还有可储藏改动。如果选择状态已经过期，或选中的文件当前没有改动，Forkline 会提示刷新工作区后重新选择，不会把 Git 的 `No local changes to save` 当成成功。

储藏所选大量文件时，Forkline 会保留全部去重后的选择路径，不会只处理前 120 个导致后面的文件仍留在工作区。

应用或弹出储藏前，如果 Git 判断会覆盖当前工作区里的本地修改，Forkline 会显示储藏专用中文提示，并说明原储藏仍保留在列表中。

如果储藏列表已经过期，例如某条 stash 已经被弹出、删除或被外部 Git 命令清掉，查看详情、应用、弹出或从储藏创建分支时会提示刷新储藏列表后重新选择。应用、弹出、删除或从储藏创建分支时，后端会校验页面选中时看到的 stash 提交 SHA；如果新的 stash 插入导致 `stash@{0}` 这类序号已经指向另一条储藏，操作会被拒绝，避免删错或弹错储藏。创建、应用、弹出、删除储藏和从储藏创建分支前也会校验页面看到的当前分支和 HEAD，避免旧页面把储藏应用到外部切换后的分支；应用、弹出和从储藏创建分支还会校验工作区快照，避免旧页面把储藏内容写入外部刚改过的工作区。

如果 Forkline 记住的“储藏并签出”恢复记录已经过期，例如对应 stash 被手动删除，恢复失败后会清理这条本地记录，避免反复尝试。只要仓库、实际检出分支和当前查看范围仍与该签出储藏匹配，Forkline 会直接自动恢复，不再显示“是否恢复”确认框；异步查询期间切换仓库、切换实际分支或改为查看其他分支，旧结果不会触发恢复。恢复这类自动切换储藏前，后端会确认当前分支仍是该储藏所属分支，并校验页面看到的当前分支、HEAD、工作区快照和 stash 提交 SHA，再按 `On <分支>:`、完整消息和 SHA 精确匹配，避免过期请求、近似消息或同消息新 stash 恢复到错误分支。

# 仓库状态刷新

## 手动刷新

顶部“抓取”左侧的“刷新仓库”按钮重新读取当前仓库的本地分支、提交历史和工作区状态，适用于在其他编辑器或终端修改文件、提交代码或调整分支后主动更新界面。

- 不抓取远端、不拉取、不推送，不执行暂存或提交。
- 保留提交草稿、搜索条件、历史加载深度和仍有效的选中提交，并尽量保留阅读位置。
- 查看分支与实际工作分支仍分别处理，刷新不执行分支切换。
- 刷新期间显示“刷新中…”，阻止重复点击；失败后保留已有数据并提示错误。
- 工作区原有“刷新”按钮仍仅更新未提交修改。

## 自动刷新与开销

现有自动刷新只检查工作区未提交修改，不定时重新读取全部提交历史：

- 窗口可见且获得焦点时，通常每 5 秒检查一次。
- 窗口隐藏或失去焦点时不发起工作区检查；恢复活动时安排立即检查。
- 变更文件数达到 800 且状态持续不变时，检查间隔依次延长至 10、20、30 秒；恢复变化后回到 5 秒。
- 已有快照用于省略相同状态的数据返回和界面重绘，但服务端仍运行本地 Git 状态检查，因此大仓库、慢磁盘的消耗不为零。

手动完整刷新只在点击时执行，不增加定时器或自动刷新频率。本轮未测量特定用户仓库的 CPU 和磁盘占用，不能据此承诺所有仓库开销一致。

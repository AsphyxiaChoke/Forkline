# Forkline Electron 桌面版

## 目标

Electron 版直接复用 Forkline 当前 Web 界面、服务端 Git 逻辑和全部已有功能，不维护第二套 UI。桌面进程负责选择空闲回环端口、启动 `server.js`、打开应用窗口，并在退出时协调后台服务和它持有的 Git 子进程完成清理。

## 运行

### Release 安装版

`v0.4.1` 起，正式 Release 提供 `Forkline-Setup-<version>-windows-x64.exe`：

- 仅支持 Windows x64，按当前用户安装，不要求管理员权限。
- 安装向导允许选择目录，默认创建桌面和开始菜单快捷方式。
- 卸载默认保留 `%APPDATA%\forkline` 中的窗口、缩放和页面数据，便于后续版本继续使用。
- 当前安装器未做代码签名，Windows 可能显示“未知发布者”或 SmartScreen 提示。只应从官方 Release 下载，并使用同页 `.sha256` 文件核验安装器。

安装版不需要执行 `npm install`，直接从快捷方式启动。

### 源码运行

首次试用安装依赖：

```bat
npm.cmd install
```

之后双击：

```text
start-electron.cmd
```

也可以启动时直接打开仓库：

```bat
start-electron.cmd "D:\桌面\GitTest"
```

开发命令：

```bat
npm.cmd run desktop:dev -- "D:\桌面\GitTest"
```

`desktop:dev` 会监听 `public/` 内的界面文件。修改样式或前端脚本后只刷新现有页面，不关闭或重新创建 Electron 窗口，后台服务端口和当前仓库保持不变。修改 `electron/`、`server.js` 或其他主进程/服务端文件时，仍需手动重启一次。

## 仓库路径与切换保护

- Forkline 已经运行时，再执行 `start-electron.cmd "仓库路径"` 会复用现有窗口和后台服务，把窗口拉到前台后通过受限 IPC 通道交给页面打开，不会再创建第二个实例。
- 页面仍在启动或重新加载时收到的仓库路径会先排队；连续收到多个路径时只保留最新一个，等现有页面初始化完成后再使用正常的渐进切仓流程。
- 启动参数对应仓库的服务端预加载如果暂时失败，Electron 不再直接退出；主窗口仍会打开，并把该路径交给页面按正常仓库打开流程重试和本地降级。
- 手动输入路径、最近仓库、目录选择器和桌面第二实例共用 `openRepo`；克隆后打开与初始化后打开也复用相同保护。文件编辑器有未保存修改或提交信息框有草稿时，会列出具体内容并要求确认后才切仓。
- Windows 盘符路径只存在大小写、斜杠方向或末尾斜杠差异时按同一仓库处理，不会重复弹出丢失内容提示；其他平台的全局仓库快照比较规则不变。

## 最近仓库持久化

- Electron 后台服务每次启动继续选择随机 `127.0.0.1` 端口，但 `v0.4.4` 起最近仓库不再依赖端口对应的浏览器 `localStorage`，而是保存在 `%APPDATA%\forkline\desktop-recent-repositories.json`。因此重启、覆盖安装或应用内更新后即使回环端口改变，最近仓库仍属于同一份桌面数据。
- 第一次升级且稳定文件尚不存在时，主进程只扫描 Electron 既有 `Local Storage\leveldb` 中出现过的回环来源；随后用隐藏、沙箱化的 Chromium 页面读取固定键 `forkline-recent-repos`，按最近时间合并、按路径去重并最多保留 `10` 条。迁移不会删除或重写旧 LevelDB。
- preload 只暴露固定的最近仓库读取和写入方法；主进程只接受当前主窗口 `webContents` 的调用。渲染页不能传入文件路径、IPC 名称或任意本机文件操作。
- 普通 Web 浏览器和 Web 便携版仍使用各自来源下的 `localStorage`，现有菜单、Git 语义和便携版更新方式不变。NSIS 卸载继续保留 `%APPDATA%\forkline`，重装后会继续读取稳定记录。

## 界面缩放

- 新安装默认使用 `90%`，用于减少高 DPI 和较窄窗口中的顶部栏拥挤。
- 可在右侧“设置 -> 界面缩放”中选择 `75%`、`80%`、`90%`、`100%` 或 `110%`。
- 快捷键为 `Ctrl+-` 缩小、`Ctrl++` 放大、`Ctrl+0` 恢复默认 `90%`。
- 选择结果会自动保存在 `%APPDATA%\forkline\desktop-preferences.json`，下次打开继续使用。
- 缩放仅影响 Electron 窗口，不修改 Windows 系统缩放，也不影响浏览器版。

## 窗口位置

- 首次启动仍使用默认尺寸并最大化；之后会恢复上次所在屏幕、普通窗口尺寸和最大化状态。
- 窗口状态保存在 `%APPDATA%\forkline\desktop-window-state.json`，与界面缩放偏好分开保存。
- 双屏缩放比例不同时，恢复前会按 Electron 的显示器工作区校正窗口，避免每次先在主屏创建后再跨 DPI 移动。
- 上次使用的显示器已经断开时，会丢弃失效坐标并回到安全默认位置；保存尺寸大于当前屏幕时会收回可用工作区。
- 需要重置窗口位置时，先关闭 Forkline，再删除 `desktop-window-state.json`。

## 应用图标

- Electron 窗口、任务栏和桌面快捷方式使用与页面左上角一致的 Forkline 三节点分叉标识，不再显示 Electron 默认图标；纵向粗线代表主线，右上支线突出 Git 分支语义。
- Windows 使用包含 `16` 到 `256` 像素九档尺寸的 `electron/assets/forkline-icon.ico`；高清预览和其他桌面平台使用 `electron/assets/forkline-icon.png`，可维护的矢量源图为 `electron/assets/forkline-icon.svg`。
- 手工创建桌面快捷方式时，目标仍指向 Electron 启动入口，图标位置选择 `electron/assets/forkline-icon.ico`。

## 卡顿与页面恢复

- Electron 收到页面无响应事件后会先等待 `2.5` 秒；页面在此期间恢复则不弹窗，避免大文件或差异计算的短暂停顿被误判为崩溃。
- 持续无响应时默认选项是“继续等待”。弹窗会列出当前仓库、有未保存修改的文件编辑器和提交信息框；只有用户明确选择放弃这些内容时才重新加载。
- 渲染进程崩溃、被结束或内存不足时，弹窗会显示原因和退出码，并提供“重新加载页面”和“退出 Forkline”。
- Electron 会把当前仓库的提交摘要、正文、追加复选框，以及未保存的工作区文件内容和查看位置保存到主进程内存。渲染进程崩溃或普通重新加载后，等仓库初始化完成再恢复这些内容，不写入磁盘，也不暴露任意 IPC。
- 文件草稿会携带打开时的 SHA-256 快照。磁盘版本未变化时恢复为可继续保存的未保存内容；磁盘版本已经变化时，编辑器改为“磁盘当前版本 / 恢复草稿”只读对照，必须复制需要的内容后重新打开文件，旧草稿不能直接覆盖新版本。
- 用户在无响应弹窗中明确选择“放弃未保存内容并重新加载”时会先清除内存草稿；退出整个 Forkline 后主进程结束，草稿也不会跨应用启动保留。

## 应用内更新

- 从官方 Git 克隆运行的 Electron 源码版可复用设置页“立即更新并重启”；更新预检、正式 Release Tag、干净工作区、`main` 分支和快进限制与 Web 版一致。
- 后台服务会把 Electron 主进程 PID、可执行文件和应用入口写入受限更新计划。更新器准备完成后，后台服务只通知当前 Electron 父进程退出，由主进程沿用正常关闭流程清理 HTTP 服务和 Git/SSH 子进程。
- 更新器等待整个旧 Electron 实例退出后才快进代码，并重新启动 Electron 入口。新窗口到达 `ready-to-show` 后，会在 `%TEMP%` 下写入限定名称的健康标记；只有 PID 和目标版本都匹配才算更新成功。
- 新桌面实例未能启动或未写入健康标记时，更新器只终止本次启动的进程树，使用 `git reset --keep` 恢复更新前提交，并重新打开旧桌面版本。
- NSIS 安装版在打包后的 Windows 环境启用 `electron-updater`，启动后检查 GitHub 正式 Release，但不会自动下载或静默安装。设置页继续使用“立即更新并重启”，只有用户点击后才下载目标安装包。
- `v0.4.2` 起，GitHub 官方 `latest.yml` 继续决定最新版本、安装器文件名、大小和 SHA-512；只有白名单内的 Forkline Windows x64 EXE 与 blockmap 会改写为 `https://ghfast.top/` 加速地址。渲染进程不能传入镜像、URL 或文件路径。
- 加速节点不可用、返回错误内容或 SHA-512 校验失败时，更新器会清理失败下载并关闭差分下载，自动回退 GitHub 官方完整 EXE；用户主动取消下载时不触发回退。第三方节点只承担文件传输，不成为版本或完整性信任源。
- `v0.4.1` 不包含上述下载控制器，所以从 `v0.4.1` 首次升级 `v0.4.2` 仍走 GitHub 官方源；从已安装的 `v0.4.2` 开始，后续安装版更新才会优先使用国内加速。
- 安装包下载完成后，主进程先通过后台服务确认没有 Git 操作仍在执行，再要求后台服务停止接收请求并终止当前实例持有的 Git/SSH 子进程。仍有操作或后台服务未能在有界时间内完整停止时取消安装；成功停止后才调用安装器，并要求安装完成后重新打开 Forkline。
- preload 只暴露获取状态、检查、安装和订阅状态四个固定 IPC；渲染页不能传入下载地址、可执行文件或任意 IPC 名称。
- 源码 Electron、Web 版和 Web 便携版继续使用原有 Git 快进更新，不会误走安装器更新。GitHub 自动生成的源码 ZIP 仍不支持任一一键更新方式。

## 运行边界

- 页面仍只访问随机选择的 `127.0.0.1` 端口，现有 Host、Origin 和仓库快照保护继续生效。
- 渲染进程关闭 Node 集成，启用上下文隔离和沙箱；页面不能直接访问本机 Node API。
- 外部 HTTP/HTTPS 链接交给系统浏览器，不能在 Forkline 窗口内替换主页面。
- Windows 使用隐藏标题栏和系统窗口控制按钮；最上方有独立拖动标题栏，仓库、搜索和同步操作位于下一行，不再与最小化、最大化、关闭按钮重叠。
- 独立标题栏使用 Windows 原生 `40px` 按钮区域，页面通过 Electron 的 `titlebar-area-height` 环境值获取缩放后的真实高度；业务顶部栏在中等宽度下继续使用紧凑两行排版。
- 切换深色、浅色、石墨、森林、樱色或高对比皮肤时，页面会把当前顶部背景色和文字色通过受限 IPC 同步给 Windows 原生标题栏；最小化、最大化、关闭按钮会立即跟随皮肤变化，重新打开时恢复已保存皮肤后也会同步。
- Electron 后台服务在独立 Node 子进程运行。关闭最后一个窗口时，主进程先通过 IPC 请求优雅退出并等待结果，不会直接跳过服务端清理。
- 后台服务收到退出、自更新、父进程断开或终止信号后，会先停止接收新请求，再终止 Git 运行时持有的全部命令，包括普通历史、Diff 等只读查询；关闭 HTTP 连接后才结束自身。
- 优雅退出有时间上限；超时后 Electron 只对自己 fork 的后台服务句柄及其进程树兜底，不按进程名扫描，不会终止其他终端或 Git 工具中的 Git/SSH。
- 普通移动、拉伸、最大化和还原会延迟合并后保存，避免拖动过程中频繁写磁盘；关闭窗口前会立即刷新一次状态。
- `desktop:dev` 只在未打包开发环境启用页面监听；普通 `desktop`、`start-electron.cmd` 和正式打包程序不会监听源文件。

## 当前定位

Electron 桌面版与 Web 版共用界面、Git 语义和后台服务。`v0.4.1` 新增 Windows x64 NSIS 安装器、安装器级应用内更新和 Release 自动构建；`v0.4.2` 为安装版的后续应用内更新加入受限国内下载加速与官方源回退；`v0.4.4` 把 Electron 最近仓库迁移到不受随机回环端口影响的稳定用户数据文件。Web 便携包及其 Git 快进更新保持不变。

当前发布边界仍是不签名安装器。发布说明必须明确未知发布者与 SmartScreen 风险；后续若加入代码签名，应发布新版本，不得替换已发布版本的信任边界说明。

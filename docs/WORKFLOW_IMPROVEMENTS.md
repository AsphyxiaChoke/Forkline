# 日常操作动线优化

以下为本地源码改动，安装版状态以 progress.md 最后的打包记录为准。

## 1. 文件操作范围

- 工作区顶部明确显示“储藏全部”“暂存全部”“丢弃全部更改”，悬停说明包含筛选之外的文件。
- 分区内所选操作显示准确数量，折叠或尚未渲染的已选文件也计入；工作区与暂存区各自计算，不改变现有 Git 动作及丢弃确认。
- 验证：workflow-ui、issue-interactions、file-editor-ui 定向测试通过，覆盖 805 个文件超出初始渲染范围时的计数。

## 2. 提交模式与草稿

- “追加”更名为“修改上次提交”，提示会重写 SHA。普通与修改模式在当前页面内分别保留输入，切回普通模式恢复原推送选择。
- 上次提交的异步读取不得覆盖用户已输入内容或已恢复的普通草稿；HEAD 变化后不套用上一份修改草稿，不更改现有恢复草稿存储结构。
- 验证覆盖反复切换、HEAD 变化、切换后迟到响应及读取期间输入。

## 3. 工作分支与查看分支

- 侧栏固定显示工作分支；提交表单固定显示“提交到：main”。查看其他分支时同时显示“正在查看：feature”，分离 HEAD 单独提示。
- 点击分支名称仍只查看历史，“切换”仍负责真正切换。提交操作区允许换行，避免更明确的标签挤出面板。
- 验证覆盖查看不同分支、相同分支及分离 HEAD，布局定向测试通过。

## 4. 历史搜索范围

- 搜索框及结果数量明确标出已加载条数；有更多历史时，列表底部显示“继续搜索更早历史”。
- 每次点击沿用当前分支和关键词继续加载一页，仍受现有 5000 条上限约束，不冒称全仓库搜索。
- 验证从 120 条继续加载到 240 条且不清空关键词，历史耗尽不显示多余入口。

## 5. 同步后保留查看位置

- 抓取、拉取和推送系列动作保留已加载历史深度、选中的提交与顶部可见行偏移；列表顶部新增提交时按原可见提交恢复位置。
- 原选中提交不在刷新结果中时回退到有效提交；创建或修改提交后切回实际工作分支、清空历史搜索，并让新提交进入可见区域。沿用现有核心状态读取和失效响应检查。
- 验证新增提交插入、原提交消失、创建新提交及 240 条读取深度。

## 6. 日常操作确认

- 抓取、暂存全部、普通创建提交直接执行，沿用现有忙碌状态和结果反馈。
- 提交并推送、拉取、推送、丢弃、修改上次提交与强推仍保留确认；取消后不发起写入。所选暂存原本就不需要重复确认，保持不变。
- 验证普通动作不弹确认，远端或改写/丢弃动作取消后没有 API 写入。

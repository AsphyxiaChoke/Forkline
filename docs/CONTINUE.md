# Forkline 继续开发记录

## 当前状态

- 远端 `origin/main` 已拉取并基于最新代码开发。
 - 真实 Git API 自动回归底座已接入：`npm test` 使用 Node 内置 `node:test`，自动启动随机端口 Forkline 服务并在系统临时目录创建/清理独立父仓库与子模块仓库；当前固定覆盖普通 stash 创建/应用/弹出、gitlink stash 创建拦截和旧坏 stash 保留、隐藏脏子模块下“储藏并签出”不能先创建 stash 再失败、认证诊断按需加载/缓存、状态读取优化后的 Git 语义，以及 reflog 独立接口。另有零依赖前端状态测试验证切仓库后旧 reflog 响应不会写回，以及工作区内容快照和焦点轮询边界。测试隔离用户/系统 Git 配置，不使用 `D:/桌面/GitTest` 或业务仓库。
- 已完成“远端分支 checkout”：远端分支列表现在有可见的“签出”按钮，右键菜单也支持“签出为本地分支”。
- 查看其他分支的切换速度已优化：分支/Tag 视图切换改用轻量 `/api/ref-state`，只刷新提交图数据，不再每次重跑同步、认证、子模块、恢复点和工作区全量状态；如果切到已删除的远端分支 tracking，`/api/ref-state` 会自动 `fetch --prune` 并拒绝显示旧提交，前端会保留当前视图和详情。
- 当前仓库 `/api/state` 全量刷新已优化：没有 `.gitmodules` 时直接返回空子模块状态，不再启动耗时明显的 `git submodule status --recursive`；首轮已读取的当前分支、HEAD、tracking、远端和工作区状态会复用于同步详情和当前 worktree，工作树/子模块/工作区/同步详情改为并行生成。对当前 Forkline 仓库的旧服务/新服务交替实测从平均 1294.0 ms 降到 331.6 ms，下降 74.4%，排除运行日志等瞬态字段后的完整业务状态 JSON 一致。
- HEAD reflog 已从 `/api/state` 拆成按需 `/api/reflog`：只有打开“恢复点”页才读取 80 条引用日志，并提供“刷新”；前端以仓库路径、当前分支和 HEAD 为数据键，切仓库或 HEAD 变化会丢弃旧响应。当前 Forkline 仓库全量响应从 62,981 字节降到 38,264 字节，减少 39.2%；旧状态里的 reflog 与新接口结果完全一致，其余业务状态 JSON 也一致。
- 工作区自动刷新已优化：每个文件的内容 `snapshot` 进入刷新签名，同一个 `M` 状态下继续编辑也会更新文件列表和当前 Diff；5 秒轮询只在页面可见且浏览器有焦点时执行，切回页面或重新聚焦会立即静默检查。当前仓库 `/api/worktree` 实测平均 128.2 ms，避免失焦后台继续每分钟发起原有 12 次读取。
- 当前分支和当前 HEAD 提交已高亮：左侧分支列表、顶部分支条会标出真实检出分支；提交图会用 `HEAD` 徽标和独立行高亮标出当前仓库 HEAD。
- Windows 下启动 `node server.js` 后会自动打开 `http://127.0.0.1:<PORT>`，非 Windows 环境保持只启动服务。
- 本地 API 的 POST 请求已加内容类型边界：只接受 `application/json`，`text/plain` 等简单请求会被拒绝，避免外部网页用 no-cors 简单 POST 绕过前端确认触发克隆、初始化或 Git 写操作。
- 中文仓库路径的请求头错误已修复：此前 `X-Forkline-Repo-Path` 直接放入 `D:\桌面\...` 会让浏览器在 `fetch` 前抛出非 ISO-8859-1 / `ByteString` 错误；现在前端统一发送 `v1:` 加 URI 编码的 ASCII 值，服务端统一解码并拒绝畸形编码，同时兼容旧页面的英文原始路径。
- 顶部路径选择器已恢复并整理布局：路径输入框旁有固定可见的“选择”按钮，可在内置目录弹窗中进入上级目录、跳转输入路径，并通过桌面、下载、文档、用户目录和磁盘根目录快捷入口选择本机 Git 仓库；最近仓库和路径操作按钮已分组，窄宽度会提前换成两行顶栏，避免互相挤压或变形；连续打开多个仓库时只保留最后一次打开结果；有 Git 操作运行时会暂时阻止切换仓库和新的 Git 操作，避免命令执行到错误仓库或多个命令同时修改仓库状态；切换仓库期间旧工作区自动刷新、旧工作区 Diff、旧工作区按块/按行动作刷新、旧文件动作刷新、旧储藏详情/动作刷新、旧同步/远端动作刷新、旧分支/Tag/worktree/子模块/补丁动作刷新、旧提交补丁复制/下载结果、旧历史/reset 动作刷新、旧历史重写预览、旧恢复点动作刷新、旧操作日志/运行中状态刷新、旧提交详情/文件历史/逐行追踪/比较读取不会覆盖新仓库页面；仓库相关 API 请求会携带请求发起时的仓库路径，服务端发现请求来自旧仓库时会拒绝读取或执行，写操作缺少仓库上下文也会拒绝，避免多页面、旧脚本或旧弹窗把操作打到当前新仓库；后端状态、提交详情、补丁、文件历史、逐行追踪、比较、历史重写预览、工作区 Diff 和储藏详情读取会使用请求发起时的仓库路径快照，避免一次响应混入旧仓库和新仓库数据；打开新仓库或工作树会清空旧仓库的分支/Tag/mainline 弹窗、储藏详情、文件历史、逐行追踪、比较结果、最大化对照、历史编辑计划和右键菜单上下文；克隆或初始化期间如果用户又手动打开其他仓库，完成后的旧自动打开结果不会覆盖当前仓库；目录列表会隐藏 `.git`；快速切换目录时只保留最后选择的目录结果，旧请求或旧错误不会覆盖当前目录。

- 补丁工作流已接入：提交详情、提交右键菜单和命令面板支持把选中提交导出为 `git format-patch` 文本、复制补丁或下载 `.patch`；命令面板新增“应用补丁”，可粘贴 `.patch` / `git diff` 内容并选择用 `git apply` 写入工作区或用 `git apply --index` 直接暂存；应用补丁会携带页面看到的当前分支和 HEAD，后端发现外部切换分支或移动 HEAD 时会拒绝旧页面请求。
- 签出规则：`origin/feature/a` 会创建或切换到本地 `feature/a`；如果本地分支已存在就直接切换；工作区有修改时继续使用“保留 / 储藏 / 强制”的中文确认流程；本地/远端签出会校验页面看到的工作区快照，避免旧页面把外部刚出现的改动一起丢弃或储藏。
- 远端名包含 `/` 的签出和删除提示已修复：例如远端名 `team/origin` 下的 `team/origin/feature/a` 会签出本地 `feature/a`，删除确认命令显示为 `git push team/origin --delete feature/a`，不再误切成远端 `team` / 分支 `origin/feature/a`。

- 本地分支列表已显示 upstream、领先/落后数量和上游丢失状态；当前分支没有 upstream 时显示“未设置 upstream”。
- 本地/远端分支列表不再只返回前 32 条：`/api/state` 会把全部本地分支和已识别远端分支返回给前端，避免分支很多时后面的分支无法切换、比较或整理。
- 顶部“推送”已改为智能推送：已有 upstream 时执行 `git push`；没有 upstream 时优先执行 `git push -u origin <当前分支>`，没有 `origin` 则使用第一个远端。
- Fetch / Pull / Push 同步摘要已接入：操作完成后会显示当前分支 upstream、同步状态、领先/落后变化，以及远端新增/更新/删除引用；无 upstream 智能推送会显示“跟踪变化：未设置 -> origin/... ”。
- 安全强推已接入：顶部工具栏新增“强推”，当前本地分支右键菜单新增“安全强推当前分支”，后端执行带显式 upstream 提交 lease 的 `git push --force-with-lease=refs/heads/<分支>:<页面看到的upstream提交> <远端> HEAD:<分支>`；普通 push 非快进拒绝、旧页面 upstream 提交过期和 force-with-lease stale 拒绝都有中文提示；后端会拒绝把安全强推打到 `main` / `master` / `develop` / `dev` / `trunk` 这类远端主干/长期分支。
- 右侧“同步”页已接入：显示当前分支 upstream、同步状态、操作建议、待拉取提交和待推送提交，并提供抓取 / 拉取 / 推送 / 安全强推入口。
- 无提交分支的同步保护已接入：当前分支还没有首个提交时，后端会返回 `unborn = true`，同步页、命令面板和分支右键菜单会禁用普通推送 / 安全强推 / 设置 upstream，并提示先创建首个提交；后端推送、强推、设置 upstream 和无 upstream 拉取也会返回中文原因，不再误报“游离 HEAD”或透出英文 Git 提示。
- 同步页远端仓库管理已接入：显示 `git remote -v` 的 fetch / push URL，支持添加远端、抓取全部远端、抓取单个远端、修改 URL、删除远端；远端行右键菜单也提供抓取、修改 URL、复制 URL、删除远端，并显示对应 Git 指令；远端名允许 Git 合法的带 `/` 名称，例如 `team/origin`；抓取全部远端会携带页面看到的远端列表和 fetch/push URL，抓取指定远端、修改 URL 或删除远端会携带页面看到的单个远端 fetch URL 和完整 push URL 列表，后端发现远端 URL 已被外部命令改过时会拒绝旧页面请求，避免旧页面覆盖、删除或抓取新的远端配置。
- 远端连接检查已接入：同步页远端行和远端右键菜单新增“检查连接”，后端执行只读 `git ls-remote --heads <远端>`，成功时显示 fetch/push URL 和可读取分支数；认证、权限、DNS、网络、证书等常见失败会转成中文排查提示。前端同步页现在会保留最近一次检查结果，显示 URL、检查命令、成功/失败状态、Git 输出摘要和下一步建议，不再只依赖 toast。
- 远端诊断向导已接入：同步页和远端右键菜单把“检查连接”升级为“诊断连接”，失败结果会按 SSH、HTTPS、权限/仓库、DNS/网络、证书、URL/本地路径或未知问题分类，显示中文判断、排查步骤和可复制诊断命令；失败响应也会带回结构化 `remoteCheck`，前端不再只能靠错误字符串猜测。
- 同步认证助手已接入并完成按需加载优化：同步页会根据远端 URL 区分 SSH / HTTPS / 本地路径，读取本机 `~/.ssh` 中可见的 key 文件名和配对状态，检测 `ssh-agent`、Git Credential Manager，并提供 `git remote -v`、`ssh-add -l`、`ssh -T git@host`、`git credential-manager diagnose` 等可复制命令；不会读取或展示私钥内容。普通 `/api/state` 刷新不再执行这些本机探测，只有进入同步页才请求 `/api/auth-diagnostics`；结果按仓库路径和完整远端 URL 缓存 60 秒，远端配置变化自动失效，页面可点“重新检测”绕过缓存，旧仓库或旧远端请求返回时不会覆盖当前页面。
- PR/MR 快捷入口已接入：同步页会为当前本地分支生成 Pull Request / Merge Request 创建链接，支持 GitHub、GitLab、Bitbucket 和常见 Gitea / Forgejo 网页远端；可在同步页、命令面板、当前分支右键菜单中打开或复制链接，本地路径远端会显示中文不可用原因；快速切换仓库时，目标分支推断会使用请求发起时的仓库路径快照。
- PR/MR 目标分支推断已跟随真实远端名切分：如果当前分支 upstream 是 `team/origin/main` 这类远端名含 `/` 的引用，目标分支会推断为 `main`，不会误生成 `origin/main`。

- 历史、同步和比较的单文件 Diff 匹配已改为精确路径：前端 `diffForFile` 会从 `diff --git`、`---/+++`、rename/copy 元信息中抽取候选路径再做相等比较，不再用 `includes`，避免选择 `foo.txt` 时误显示 `dir a/foo.txt` 的改动。
